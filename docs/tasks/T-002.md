## Goal
Run one tiny scripted task with `claude -p --output-format stream-json` in a scratch worktree, capture the raw JSONL,
parse **every** event type into a summary, resume the same session by ID with a follow-up prompt, and document the
event shapes (including rate-limit and error shapes) for the adapter interface (T-004).

## Design
- `run.sh`: `spike_require_live`; scratch repo + worktree `claude-1`; then, with cwd = the worktree:
  `claude -p "<TASK>" --output-format stream-json --verbose --permission-mode acceptEdits`
  TASK: "Create hello.txt containing exactly the line: hello from claude. Then reply DONE."
  If `claude --help` lists a max-turns option, pass a value of 5 or less (rule 1 ceiling is 40). If it doesn't, add a
  watchdog that kills the child's process group after 120 s. stdout → `captures/.../raw.jsonl`, stderr → `stderr.txt`.
  Then run `parse.jq` and print the summary. **One invocation per run. No retries, no loops.**
- `parse.jq` (input: JSONL via `jq -s` or `--slurp`): outputs `{session_id, event_counts: {"<type>/<subtype>": n},
  tool_uses: [names], final: {is_error, num_turns, duration_ms, usage, total_cost_usd, result_excerpt (≤200 chars)},
  limit_or_error_events: [...], unknown: [...]}`. It must never fail on an unknown type: keep it in `unknown`.
- `resume.sh <capture-dir>`: `spike_require_live`; reads `session_id` from that capture; runs
  `claude -p --resume <id> "Append a second line to hello.txt: resumed. Reply DONE." --output-format stream-json --verbose`
  in the same worktree; records whether the session id is reused and whether hello.txt has both lines.
- `EVENTS.md`: a table of every type/subtype, marked **observed** (from a live capture) or **from docs** (with link),
  each with a redacted one-line example. Rate-limit/usage-exhausted shapes: take them from official docs and mark them
  "from docs". **Never try to provoke a rate limit.**
- Fixtures: `sample.jsonl` hand-written from docs (so tests work before any live run). After the human's live run,
  add `observed.jsonl` = `spike_redact` of the real capture, reviewed by the human before commit.

## Hard rules touched
| Rule | How | Test |
|---|---|---|
| 1 | One human-triggered invocation, small turn cap or watchdog, no loops | test asserts run.sh exits 3 without `SPIKE_LIVE` and makes no CLI call |
| 2 | Default config home only; no config-home variables named | compliance scan |
| 3 | Headless `-p` only. Never starts interactive `claude`, no PTY, no expect/tmux send-keys | code review + scan |
| 4 | Never reads Claude's credential files; captures redacted before commit | scan; test greps fixtures for `@` and `/Users/` → none |
| 10 | No retry on error: report and exit | review |

## Acceptance criteria (runnable)

- [ ] `/bin/bash spike/tests/test_claude_parse.sh` exits 0, offline. It parses `sample.jsonl` and asserts: session_id

      summary; `SPIKE_LIVE=1 spike/claude/resume.sh <capture-dir>` appends the second line.
- [ ] EVENTS.md covers every type/subtype in the fixtures.

## Notes / open questions
- The implementer must **not** set `SPIKE_LIVE=1`. Live runs use the human's subscription and are run by the human.
- If `--permission-mode acceptEdits` isn't enough to write the file headless, record what was needed. Never use
  `bypassPermissions`.
