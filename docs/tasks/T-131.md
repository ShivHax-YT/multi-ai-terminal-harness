# T-131: App command wiring: sessions, terminal bridge and the gated pty_write, usage, and the Tauri event emitter

Status: draft
Phase: 1   Model hint: opus (PTY input gate, rule 3; the only opus writer at its time)
Depends on: T-112 (usage snapshot), T-113 (pacing for `resume_provider`), T-123 (pty-view), T-124 (session manager)   Runs: wave 11, alone as the only opus writer

## Goal
Replace the T-101 stubs for the session, terminal, and usage commands with real handlers, and build the one Tauri
event emitter that every harness-core `EventSink` uses. The only code that can write bytes to a PTY is the `pty_write`
handler, and it writes only when the session's take-over flag is on and the caller is the UI's `PtyInputPort`. The
scheduler, lead and every other harness-core module cannot reach this code (rule 3).

## Design
1. **pty_write gate (rule 3).** `pty_write({session_id, data})`: (a) look up the session; (b) refuse with `rule_blocked`
   3 unless `SessionView.takeover` is true; (c) refuse if the session is `exited` or `killed`; (d) refuse data over 4 KiB
   per call; (e) write the bytes to the session's `InteractivePty` only. A refusal is returned, never retried. Login
   sessions have takeover on by construction (T-101).
2. **No automated caller.** The handler is registered as a Tauri command only. The app's Rust code has no other call site
   for `write` (a test greps the workspace for `.write(` on PTY types outside `pty_bridge.rs` and `pty.rs`).
3. **Output path.** The runner's raw stdout is teed into an app-owned transcript file (under app data) and the bytes go to
   the `ViewPty` mirror for that session. `terminal_output` events carry `seq` and base64 bytes. The transcript is
   deleted when the session is removed (no retention beyond the session).
4. **attach / resize.** `attach_terminal` returns `{cols, rows, scrollback_b64}` from the ring (cap per T-123 decision).
   `resize_terminal` resizes the PTY only.
5. **Takeover.** `set_takeover(enabled)` calls the session manager (pauses automation with reason `takeover`) and, when
   enabling, starts the `InteractivePty` takeover CLI in the worktree through `pty-view`. Disabling stops input forwarding
   and leaves the session paused until `resume_session`.
6. **Session commands.** `pause_session`, `resume_session` (refused during backoff with rule 10 and at a ceiling with
   rule 1, from T-124), `kill_session` (runner cancel). `list_sessions` returns full snapshots.
7. **Usage.** `get_usage` builds `UsageSnapshot` from the usage store (T-112) and pacing (T-113). `resume_provider` calls
   pacing's user resume; it is refused while the backoff window is open. No command resets a counter.
8. **Events.** `EventSink` impl emits Tauri events with full snapshots. Events are emitted after state changes only.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 3 | pty_write refused without takeover; the only PTY write call site | `cargo test -p app pty::write_refused_without_takeover` and `cargo test -p app pty::single_write_call_site` (greps the workspace) |
| 3 | Scheduler and lead cannot reach the write path | `make crate-boundary` and `cargo test -p app pty::no_write_from_scheduler_or_lead` (greps `commands/lead.rs`, `scheduler/`, `lead/` for `pty_write`, `write(`) |

| 3 | Chunks over 4 KiB refused | `cargo test -p app pty::chunk_cap` |
| 10 | Resume during backoff refused and reported | `cargo test -p app sessions::resume_refused_backoff` |
| 1 | Resume at ceiling refused | `cargo test -p app sessions::resume_refused_ceiling` |
| 2 | Usage has no reset command; a sign-out status change leaves counters unchanged | `cargo test -p app usage::no_reset_command` and `usage::signout_keeps_counters` |
| 4 | Transcript is app-owned and deleted with the session; no CLI home path | `cargo test -p app pty::transcript_deleted_with_session` |
| 5 | No listener added by the bridge | covered by T-130 `no_listener` (regression) |
