# T-103: Lead screen (front door and thread)

Status: draft
Phase: 1   Model hint: sonnet
Depends on: T-101 merged   Runs: wave 2, parallel with T-105 and T-107 (no shared files)

## Goal
A calm front door: one prompt box that sends a request to the chosen lead, a thread that shows the lead's reply as plain text, and a route into plan review (T-104). The lead never approves a plan, never sees a terminal and never writes to a PTY (rules 3 and 9).

## Design pre-flight (before code)
- **Screen goal:** Say what to build. The lead turns it into a plan you review.
- **Primary action:** Send (filled) while idle, ⌘Enter. While `thinking`, Send is disabled and Cancel is outline. When a request reaches `plan_ready`, "Review plan" is the only filled button and Send becomes outline.
- **Tokens:** `--card` (prompt surface, solid, 14px radius), `--input` (border), `--foreground`, `--muted-foreground` (limits line), `--primary` (Send / Review plan), `--warning` and `--destructive` with icon and text for rate limit and error. Inter throughout; no mono.
- **Typography:** H1 24px semibold. Prompt 16px. Limits line 14px muted. The lead's spec says 13px; `docs/design/README.md` sets small text at 14px, so this brief uses 14px (see Notes).
- **Wireframe, 1024 px** (front door):
```
+--------------------------------------------------+
| What do you want built?                          |
| +----------------------------------------------+ |
| | Add a dark-mode toggle to settings           | |
| |                          [lead v]  [Send]    | |
| +----------------------------------------------+ |
| [Dark-mode toggle] [Fix parser test] [Tests..]   |
| Plans need your approval. Subscription use is    |
| capped.                                          |
+--------------------------------------------------+
```
- **Wireframe, 1440 px** (content column 720 px, centred; the thread sits below the prompt):
```
+----------+---------------------------------------------------------+
| Sidebar  |            What do you want built?                      |
| (240 px) |     +-----------------------------------------------+   |
|          |     | Add a dark-mode toggle to settings            |   |
|          |     |                          [lead v]  [Send]     |   |
|          |     +-----------------------------------------------+   |
|          |     [chip] [chip] [chip] [chip] [chip]                  |
|          |  you:   Add a dark-mode toggle to settings              |
|          |  lead:  thinking...   (Shimmer on the lead card)        |
+----------+---------------------------------------------------------+
```
- **Signature motion:** Stagger (Animated Group) on the starter chips, once, at most 300 ms, 40 ms step. Text Shimmer on the lead card's "thinking" line is status feedback, not a second signature. If Text Shimmer is not approved (see T-101 notes), the `Shimmer` wrapper's opacity-pulse fallback is used.
- **Inspiration technique borrowed:** Dribbble AI-app tag: a solid prompt bar with starter chips.
- **Placeholder rotation:** five example requests, one every 4 s, only while the box is empty and unfocused. The first example is fixed under reduced motion. Nothing changes while the user types.
- **States (each rendered from a mock scenario and tested):**
  - Loading: `LoadingSkeleton` in the thread while `list_lead_requests` is pending (`ready`).
  - Empty: front door only, no thread (`ready`, no requests).
  - Thinking: send, then `control.advance(1500)` gives `plan_ready` (`ready`).
  - Rate limited: `Countdown` "Lead paused until <time>" and "Choose another lead" (`rate_limited`).
  - No usable lead: picker disabled with "No lead is ready. Check Providers." (`fresh`).
  - Error: `ErrorAlert` with retry = refetch (`errors`).

## Behaviour
- **Lead picker:** a shadcn `Select` beside Send. Options are providers from `list_providers()` with `usable.lead === true`, shown with `ProviderName`. Gemini appears only when `usable` says so (API key present, rule 7).
- Starter chips fill the prompt. They never send. Send is the only way a request starts.
- Lead text (`messages[].text`, `error`) renders only in `UntrustedText`. Markdown and HTML stay literal. Nothing is auto-linked.
- "Review plan" navigates to `planPath(plan_id)`. It never calls `approve_plan`.
- The composer is disabled while a request is `thinking` (one request in flight).
- Do not auto-retry on `rate_limited` or `rule_blocked` (rule 10).

## Notes / open questions
- **Limits line size:** 14px per the design README, not the 13px in the lead's spec. Confirm.
- **Signature:** the chip stagger is the one signature. Shimmer is state feedback, not a second signature. Confirm.
- **Auth mode:** `start_lead_request` takes `{lead, text}` only, but the in-flight plan schema adds `lead.auth_mode`. Request to the lead: confirm the backend picks the auth mode from `usable`, or add an argument.
- **Copy:** provider names are never typed into copy. Use `ProviderName` or `providerLabel`. A literal provider name in a non-test file fails rule 8.
