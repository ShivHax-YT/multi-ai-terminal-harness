## Design
1. **adapter-interface.md** (language-neutral). For each method: signature, preconditions, errors, rules.
   - `start(task, worktree) -> SessionId`, `send(prompt)`, `events() -> stream`, `cancel()`, `authStatus() ->
     SignedIn|SignedOut|Unknown`, `capabilities() -> {transport, resume, mcp, hooks, native_turn_cap}`, `usage()`, and
     `loginArgv() -> argv | none` (approved; requested by T-120). It returns only the CLI's own documented login
     command and nothing else (no flags that change accounts or config homes, rule 2); none for API-key-only providers
     (rule 7); the login runs in a PTY driven only by the human (rule 3).
   - `send` starts the next headless invocation with resume by session id. It never writes to a live child; child stdin
     is /dev/null. `transport` is `headless | acp`; there is no pty value; the registry rejects an adapter with neither.
   - `authStatus` = the CLI's documented status command (`claude auth status`, `codex login status`), exit code only,
     output discarded (rule 4). Preconditions of `start`: verified binary (6), default config home, env allowlist (2),
     worktree outside CLI homes (4), approved plan token checked by the scheduler (9).
   - **State machine** (table: from, trigger, to). States `spawning, running, idle, rate_limited, exited, killed`
     (the T-120 set). `paused` is a flag owned by T-124, not a state. Key rows: process start -> spawning;
     `session_started` -> running; `result{is_error:false}` + exit 0 -> idle (resumable); exit without a result, or
     `result{is_error:true}` -> exited; any `rate_limited` in an invocation -> rate_limited at exit (counted once per
     invocation; later ones only raise `reset_at`); backoff over or user resume -> idle; `cancel()`/watchdog -> killed.
     Rule 10 timings are referenced, not redefined. A limit never starts a new session on the same provider (rule 2).
   - **Turns:** `result.turns` = turns used by that invocation: Claude `num_turns`; Codex 1 per `exec` call.
2. **event.schema.json** (JSON Schema 2020-12). Every event: `type, provider, seq` (1-based raw line), `ts`
   (string or null; jq leaves null unless `--arg ts` is given), `raw` (the raw key it came from). Types:
   `session_started{session_id}`, `message{role:"assistant", text, truncated}`, `tool_call{id, name}`,
   `tool_result{id, is_error}`, `warning{kind, message}`, `limit_notice{status: allowed|allowed_warning,
   utilization?, reset_at?}`, `rate_limited{raw_kind, reset_at?, retry_after_s?}`, `error{kind, fatal, message}`,
   `result{is_error, subtype?, turns, tokens{input, output, cache_read, cache_write, reasoning}, tokens_known,
   cost_usd?, cost_is_estimate, stop_reason?, duration_ms?}`, `exited{code?, signal?}`, `unknown{raw_type, keys}`.
   `$defs.transport` = enum `["headless","acp"]`; `$defs.capabilities` uses it.
3. **Mapping, Claude** (raw key = `type` or `type/subtype`; content blocks as `assistant:text` etc.):
   `system/init` -> session_started; `assistant:text` -> message; `assistant:tool_use` -> tool_call; `user:tool_result`
   -> tool_result; `assistant` with `.error == "rate_limit"` -> rate_limited (`claude_assistant_rate_limit`), other
   `.error` -> error (fatal false); `rate_limit_event` with `rate_limit_info.status == "rejected"` -> rate_limited
   (`claude_rejected`, or `claude_credits_required` when `errorCode` says so; `reset_at` = `resetsAt`); any other or
   missing status -> rate_limited (`claude_unknown_limit_status`, fail safe; human decision 2026-10-26). Only `allowed`
   and `allowed_warning` -> limit_notice; `system/api_retry` -> warning (the CLI retries itself);
   `system/permission_denied` -> warning; `result/*` -> result (cache_read = `cache_read_input_tokens`, cache_write =
   `cache_creation_input_tokens`, reasoning 0, `cost_is_estimate` true), preceded by rate_limited (`claude_result_429`)
   when `is_error` and `api_error_status == 429`.
   **Ignored:** `system/status`, `system/thinking_tokens`, `assistant:thinking`, `assistant:redacted_thinking`,
   `user:text`, per-message `assistant.message.usage` (the result has the totals).
4. **Mapping, Codex:** `thread.started` -> session_started; `item.started` of a tool item (`command_execution`,
   `file_change`, `mcp_tool_call`, `web_search`) -> tool_call{name = item type}; `item.completed` of a tool item ->
   tool_call first if none was seen for that id, then tool_result (is_error: status failed or non-zero exit code);
   `item.completed:agent_message` -> message; `item.*:error` -> **warning** (`item_error`), never error or
   rate_limited; `turn.completed` -> result (cache_read = `cached_input_tokens`, cache_write =
   `cache_write_input_tokens`, reasoning = `reasoning_output_tokens`, cost null); `turn.failed` -> error
   (`turn_failed`, fatal) + result{is_error:true, tokens 0, tokens_known:false}; top-level `error` -> error
   (`stream_error`, fatal). On those two fatal carriers only, a message matching T-003's rate-limit heuristic first
   emits rate_limited (`codex_text_hint`). Agent text is never classified.
   **Ignored:** `turn.started`, every `item.updated`, `item.started` of non-tool items, all `reasoning` and
   `todo_list` items.
5. Anything not mapped or ignored -> `unknown{raw_type, keys}` (key names only). Docs-only types (hooks, tasks,
   compaction, `system/api_error`, `system/model_fallback`, ...) stay unknown until a capture shows them.
6. **Normalizers:** `jq -c -n -R [--arg ts T] [--argjson exit_code N] -f spike/normalize/<cli>.jq < raw.jsonl`.
   Never fail: a non-JSON or non-object line -> unknown (`malformed_line`). Text: control characters except `\n`
   and `\t` become spaces; message text max 4000 chars (`truncated` true), other text max 300. Never copied: init
   tool/MCP/plugin/skill lists, `cwd`, tool inputs, commands, file paths. `exit_code` appends one `exited` last.
   Each jq file defines `mapped_keys` and `ignored_keys`; the spec repeats the ignored list between
   `<!-- ignored:claude:start/end -->` and `<!-- ignored:codex:start/end -->` markers.

## Notes / open questions
- Captures win over docs. A difference goes in the mapping table's Source column ("observed" vs "from docs").
- **Human decisions (ShivHax-YT, 2026-10-26):** (a) `loginArgv()` is in the interface and launches only the CLI's own
  login command; (b) each Codex `exec` counts as 1 turn toward rule 1's 40 turns per task (the 120 s watchdog bounds one
  call); (c) an unknown or missing `rate_limit_event` status counts as `rate_limited` (fail safe), only `allowed` and
  `allowed_warning` are notices; (d) `cost_is_estimate` is always true for subscription logins.
- No JSON Schema validator in spike/: structure is checked with jq; T-120's serde types and tests are the real check.
