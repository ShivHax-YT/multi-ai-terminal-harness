## Goal
Shared bash helpers that every Phase 0 spike uses: make a throwaway git repo **outside this repo** (so this repo's
CLAUDE.md, hooks and settings never load into the spiked CLI sessions), add/remove worktrees in it, gate live CLI
calls behind an explicit flag, redact captures, and a preflight that reports each CLI's install, version, code
signature and sign-in state using only documented commands.

## Design
- Language: bash + jq (stack-neutral; jq is already required by the kit). Must run on macOS `/bin/bash` 3.2: no
  associative arrays, no `mapfile`, no `${var,,}`.
- `spike/lib/common.sh` (sourced) provides:
  - `spike_scratch_repo` → creates `${TMPDIR:-/tmp}/harness-spike/<run-id>/repo` with one commit (a README and a
    `notes.txt`), echoes its path.
  - `spike_worktree_add <repo> <name>` → `git worktree add -b spike/<name> <repo>-wt/<name>`; echoes the path.
  - `spike_cleanup <run-dir>` → `git worktree remove --force` each spike worktree, `git worktree prune`, then remove
    the run dir. Only ever deletes paths under `${TMPDIR:-/tmp}/harness-spike/`; refuse anything else.
  - `spike_require_live` → exits 3 with a clear message unless `SPIKE_LIVE=1`. Every script that calls a real CLI
    calls this first.
  - `spike_capture_dir <cli>` → `spike/captures/<cli>/<UTC timestamp>/` (gitignored).
  - `spike_redact` (jq filter or function) → replaces UUID-like ids with `<ID-n>` (stable within a file), absolute
    paths under `$HOME` with `$HOME/...`, the scratch dir with `<WORKTREE>`, and anything email-shaped with `<EMAIL>`.
- `spike/preflight.sh`: for `claude` and `codex`: resolved path (`command -v`, follow symlinks), `--version`,
  `codesign --verify --strict` result on the resolved binary (record "not signed / not a Mach-O" honestly), and
  sign-in via `claude auth status` / `codex login status` using **the exit code only**. Never print or store their
  output (it may contain account details). Prints one table row per CLI. Also checks that jq and git exist.
- `spike/.gitignore`: ignores `captures/`.
- `spike/README.md`: what the spike is, the `SPIKE_LIVE=1` rule, the wave order, and a script index (later briefs'
  scripts listed by name as "planned").
