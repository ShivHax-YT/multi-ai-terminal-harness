## Goal
Port the plan format to Rust: a strict parser that rejects duplicate keys, invalid UTF-8 and lone surrogates, one JSON
document per read; an RFC 8785 (JCS) canonicalizer for integers and strings; the plan hash; and the rule checker
(port of `spike/plan/check.jq`). The lead's plan output, the approval binding (T-117) and the `PlanView.violations`
field all come from this module. The checker is advisory for the UI and the scheduler enforces the same ceilings at
dispatch (T-125).

## Design
1. **One read, one parse.** `Plan::from_bytes(&[u8])` takes the whole buffer and produces a value. Nothing re-reads a
   file. The caller hashes and validates the same parsed value (dispatch uses that value, never a second parse).
2. **Strict JSON.** Reject: duplicate object keys at any depth (before any other check), invalid UTF-8, lone surrogate
   escapes (`\ud800`), more than one top-level document, and any number that is not a canonical integer (`0` or
   `[1-9][0-9]*`, no sign, no fraction, no exponent, no `-0`). Integers above 2^53-1 are refused.
3. **JCS.** Implement RFC 8785 for the subset the plan can contain: objects with sorted keys (UTF-16 code unit order),
   strings with the RFC escaping rules (including U+007F emitted raw), canonical integers, booleans, null, arrays.
   Floats are not representable in a plan and are rejected at parse time.
4. **Hash.** `hash = lowercase_hex(sha256(jcs(plan_without_approval)))`. The `approval` key is removed from the parsed
   value before canonicalization, never by text editing.
5. **Shape first.** Schema-exact shape validation runs before any default is applied: unknown keys, wrong types and
   missing required fields are violations. Defaults are never filled in (plan.md).
6. **Rule checks.** Port every row of the plan.md checker table, with the same rule numbers and the same message
   substrings the spike tests assert. Output: `Vec<Violation { rule: u8, message, task_id: Option<String> }>`, which
   maps to `PlanView.violations`.
7. **Scheduler mode.** `check(plan, Mode::Pre)` (no approval needed) and `check(plan, Mode::Scheduler)` (approval
   required). The approval checks themselves live in T-117; this module only reports the presence and shape of
   `approval`.
