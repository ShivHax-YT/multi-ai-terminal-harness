# T-135: Kernel-enforced execution boundary ("broker") for repository import, worktrees, file mutation and workers

Status: proposed (needs human approval)
Phase: 1 (BUILD_PLAN lists worker sandbox defaults in Phase 4; T-133's blocker pulls the boundary into Phase 1)   Model hint: opus (unsafe FFI, descriptors, process supervision, concurrency)
Depends on: T-133, T-134 merged (they own fs_guard/**, process/**, build.rs, launch_gate.swift, status/**), T-114, T-115   Runs: sequential, alone as the only opus writer; before T-112, T-118, T-119, T-127

## Goal
T-133 (handoff, open risk 1) makes `fs_guard` refuse all file mutation and keeps repository import, `git worktree add` and workers off until a kernel-enforced boundary exists.
This brief chooses, designs and proves that boundary using fake CLIs and signed system fixtures only. Slice 1: a per-session confinement box (import, worktrees, workers,
tests, diff) plus a live attestation. Slice 2: re-enable guarded app-side mutation in `fs_guard`, only while an attestation is live. It does NOT open the native run gate:
`usable.lead/worker` stay false and `execution_boundary_unavailable` stays until the human approves a separate gate-opening task, after the human-run real-CLI spike S-3.

**ADR GATE (human decision).** ADR 0001 and the rule 4 note ship outside the Mac App Store and exclude App Sandbox because it would sandbox the child CLIs. Option A respects
that: no `app-sandbox` or `inherit` entitlement, and the app, human terminals (T-134) and status/login lanes stay unsandboxed. It does confine worker trees with a Seatbelt
profile (the same kernel facility), so "the CLIs may break" becomes a measured risk (S-3), not a ban. Option B revisits ADR 0001 outright. Nothing is built until the human
confirms A fits ADR 0001 or amends it (ADR 0002).

## Threat model (what is and is not protected)
- **Assets:** rule-4 destinations (CLI stores in `compliance/denylist.toml`, the Keychain items they own); rule-1/2/10 counters in app data (a worker that writes them dodges
  limits); the user's checkout and its `.git` hooks/config (they run later, outside any box); the app's own roots.
- **Adversary:** untrusted principals with the user's UID but less authority than the app: the worker CLI's tools, every test/build/git-hook descendant (including `setsid`
  escapees) and hostile repository content (symlinks, hard links, FIFOs, hooks, filters, includes, alternates). Trusted: the human, the app executable, the vendor main image
  after the T-133 identity gate. **Out of scope, stated plainly:** an unconfined same-UID process (it can read CLI homes directly), root, kernel bugs, anyone who can modify the app bundle.
- **Attacks in scope:** swap (a path component replaced by a symlink or another real directory between check and syscall); rename (a protected directory moved under an
  authorized name, or an authorized one moved into a protected tree: `fs_guard/tests/race.rs`); hard link, FIFO, special file; syscalls the app never sees (Git, workers, tests,
  hooks, `fsmonitor`, external diff, textconv, filters); escape by IPC (Mach/XPC, launchd, Apple Events); shared Git state; **handle reuse**: inherited or numerically reused
  fds, a writable `File` that outlives its authorization (T-133 point 3), signalling a stale PID or process group.
- **What A protects:** current destination *paths*, as the kernel resolves them at every syscall of the confined tree. It does not match object identity (inode); identity is
  covered by construction instead: reads are an allow-list and writes are deny-by-default, so a renamed credential directory stays outside both. The app keeps `identity_denied`.

## Options compared (dev Mac reports Darwin 27.0.0; nothing could be executed while writing this, so S-0 checks every behavioural claim; vendor docs read 2026-11-07)
| | A. Per-session Seatbelt profile (`sandbox_init_with_parameters`) | B. Helper with App Sandbox + security-scoped bookmarks | C. Endpoint Security client |
|---|---|---|---|
| Enforces | Every file op of the whole process tree, by resolved path, in the kernel; inherited and irrevocable; also denies Mach lookups, Apple Events and bind | The helper opens only its container and user-granted folders (positive capability) | AUTH_OPEN/RENAME/LINK/EXEC answered synchronously for any process, by path or vnode identity |
| Gaps | Host-blind network (no per-host filter without a proxy); paths, not inodes; Apple-deprecated SPI | Cannot host vendor CLIs, Git or test toolchains (inheritance breaks them, ADR 0001): covers only the app's own mutations and needs in-process Git | Root system extension, Full Disk Access and user approval; protects far more than the need |
| Cost | Medium: profile compiler, wrapper, attestation, fixtures. The `sandbox-exec` man page says DEPRECATED and omits the profile language, so OS drift is the main risk | High: new signed helper, folder-grant UX, rewrite of T-118/T-129 Git use, and A is still needed for workers | Very high: restricted entitlement ("You must request this entitlement from Apple"), hostile CI, daemon attack surface |
| Notarization | None: no entitlement, hardened runtime unchanged, still outside the Mac App Store | Helper carries `app-sandbox`: first App Sandbox use in the product, ADR revisit | Entitlement approval, system-extension packaging, consent flow |
| CLI credentials (rules 2, 4) | Profile built from compliance data lets each provider reach only its own store; HOME and env untouched; the app never opens a store; Keychain is Mach-level, not per item | Helper cannot see CLI homes, but the CLIs would then run elsewhere unconfined | Path policy; CLIs unaffected |
Also considered: **D** separate Unix user, VM or container (kernel-enforced, but the CLIs get another home and login: an alternate config home, against rules 2 and 4; rejected).
**E** descriptor-relative `openat(O_RESOLVE_BENEATH|O_NOFOLLOW_ANY)` alone (documented in `open(2)`): atomic against symlink and `..` escapes for the app's own calls, blind to
Git/worker/test syscalls; kept in Slice 2 as defence in depth. **F** the same profile applied by a separate XPC/LaunchAgent broker instead of a child wrapper: avoids fd leaks and
tripwire nesting but adds a nested signed bundle, `tauri.conf.json` changes and peer authentication; revisit if S-0 shows the child wrapper cannot meet the proofs.
Vendor precedent for A: Claude Code's sandbox is Seatbelt-based and its docs recommend an outer boundary around the whole process.

## Recommendation: Option A, plus E for the app's own calls
The "broker" stays thin: our code compiles policy and launches, the kernel enforces. Only A reaches worker, test and Git descendants, needs no Apple approval or root, is testable
unprivileged and keeps the notarized outside-App-Store flow; B cannot confine descendants and C costs far more than the risk removed. A is deprecated SPI, so every box start is
gated by a live attestation that re-proves the boundary on the running macOS build; failing it falls back to view-only, the state T-133 already ships.

## Design (Option A)
1. **Closed box types:** `Worker(provider)`, `Verify` (tests, lint), `GitRead` (diff, status), `GitAdmin` (import clone, worktree add/remove). Specs come only from compiled
   limits; plan or model text never reaches profile text.
2. **Compiled never-sets** (constants like the ceilings, no config key). Never writable: `/`, the account home itself, app data, every denylist entry, `.git/hooks`, `.git/config`,
   shell startup files, `$PATH` directories, LaunchAgents. Never readable: app data, other providers' stores.
3. **Reads are an allow-list:** system and toolchain dirs (new `compliance/box-profile.toml`, existence-checked, canonicalized), the box's roots, the provider's own store; the denylist
   overlay wins. Chosen over "read all minus denylist" because vendor docs put credential profiles in `~/.config/anthropic`, which `denylist.toml` does not list.
4. **Wrapper:** closed `--box-exec` mode of the app executable (pattern of `--provider-session`); tests re-exec the test binary through the same entry. The spec arrives on an
   inherited fd (never argv or env) and is re-validated; every fd except 0-2 and named pipes is closed; the profile is applied to itself; then it launches the target: vendor CLI
   through the existing kernel launch requirement (binds `harness_session_start`, no edit to `launch_gate.swift`), Apple-signed tools by platform requirement. stdin is `/dev/null` (rule 3).
5. **IPC and network:** Mach lookup default-deny with a short list; Apple Events, launchd domains, `network-bind` and inbound denied (rule 5); `file-link` denied on protected
   sources. `Worker` keeps coarse outbound (the CLI needs its API); `Verify` and `Git*` get none.
6. **Git:** every call on worker-controlled trees is boxed with global/system config off, hooks path nulled, `fsmonitor` off, no external diff/textconv, no optional locks. Import is a
   boxed clone into an app-owned private mirror (objects via read-only alternates); workers attach worktrees to the mirror and can never write the user's `.git` or the mirror's hooks/config (D-3).
7. **Slice 2 lane:** `fs_guard` mutation through `openat/mkdirat/renameat/unlinkat` relative to a pinned root fd with `O_RESOLVE_BENEATH|O_NOFOLLOW_ANY`; root identity re-checked by
   (dev, ino); no `File` is returned; active only with a live `BoxAttestation`, otherwise `FileMutationUnavailable` as today.
8. **Attestation:** at start and after any OS or app change, a boxed platform-signed probe tries each forbidden primitive and must see all denied while legitimate ones succeed; any
   escape fails closed and status keeps `execution_boundary_unavailable`.
9. **Supervision:** the wrapper leads its own session and process group; the app signals the group only while the leader is unreaped; app exit kills the group; no timer, retry or restart.

## The named proofs
- **`rename_race`** (macOS, same user): fake home with planted denylist dirs. A boxed fixture loops 3 s in a writable worktree `W`: rename a protected dir into `W`, rename a `W` dir
  into a protected dir, symlink and hard-link a canary into `W`, swap `W/x` for a link to app data; meanwhile the app side does guarded reads (Slice 2: writes) in `W`. Pass: every
  cross-boundary call in the fixture's result log failed (EPERM, ELOOP or ENOTCAPABLE); canary bytes and mtime unchanged; no new entry in any protected tree; at least 50 attempts and
  50 legitimate in-`W` operations. `rename_race_control` (box off, `#[cfg(test)]` only) shows the same attacks succeed, so the test can fail.
- **`canary_tripwire`** (app side): the test re-executes itself under an `(allow default)` profile that denies content access to the planted canaries with a SIGKILL modifier and runs
  every app step that needs no box: guard reads, listing and metadata, Slice 2 writes, a status probe of a platform fixture, diff and HANDOFF parsing of a finished worktree. Pass:
  never killed, while a deliberate open in a control step is.
- **`canary_box_session`** (box side): a profile cannot be applied inside an already-sandboxed process (expected; S-0 measures it), so the wrapper cannot run under the tripwire. The
  full fake session (boxed fake CLI, diff, HANDOFF) runs un-tripwired: the fake CLI reads and writes its own planted store, gets EPERM on every other provider's store and on app data,
  and the guard trace holds no canary event. Stated gap: no syscall-level audit of the app's spawn code, so T-133 risk 2 stays partly open; if stacking works, one tripwired run replaces this.
