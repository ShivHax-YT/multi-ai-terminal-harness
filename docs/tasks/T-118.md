# T-118: Worktree manager (one git worktree per worker)

Status: approved by ShivHax-YT on 2026-10-25 (hands-off authorization; lead-approved)
Phase: 1   Model hint: sonnet
Depends on: T-114 merged (paths go through `fs_guard`)   Runs: wave 2, parallel with T-112 and T-117

## Goal
Create, track and remove one git worktree per worker task, on a branch named after the task, under a root the app owns.
Workers never touch the main checkout. Every path the manager creates or deletes is checked against the file-access
layer, so no worktree can point into a CLI home directory (rule 4). Removal is safe: it refuses to delete anything
outside the managed root.

## Design
1. **Root.** Worktrees live under `<app-data>/worktrees/<repo-id>/<task-id>/`, where the caller supplies `<app-data>`.
   The `.claude/worktrees/` convention in AGENTS.md is for developers of this repo, not the app. Layout code rejects any
   root that canonicalizes into a denied directory.
2. **Create.** `create(repo, task_id, base_ref) -> WorktreeInfo { path, branch, base_commit }`. Runs
   `git -C <repo> worktree add -b harness/<task-id> <path> <base_ref>` through a `GitRunner` with an absolute git path.
   Branch names must match `[A-Za-z0-9_-]+` after the `harness/` prefix. An existing branch with that name is refused,
   never reused, so a retry cannot silently attach to old work.
3. **One per worker.** A second `create` for the same `task_id` is refused while the first exists. A worker task owns
   exactly one worktree; the scheduler (T-125) enforces one active worker in Phase 1, and the manager enforces the
   one-per-task rule on its own.
4. **Owned files.** The manager records the plan's `owned_files` and exposes `is_owned(path)` so the review and merge
   steps can list changes outside the owned set. It does not enforce file ownership by itself; it reports.
5. **Remove.** `remove(task_id)` runs `git worktree remove --force` on that path only, then `git worktree prune`. It
   refuses any path that is not under the managed root. It never deletes the branch (branches are kept for review).
6. **Git environment.** The `GitRunner` sets only `PATH`, `HOME` (unchanged, the caller's), `LANG=C` and
   `GIT_TERMINAL_PROMPT=0`. No credential helper variables are passed by this module.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 4 | Worktree under a denied directory is refused | `cargo test -p harness-core worktree::root_in_denied_home_refused` |
| 4 | Worktree never points into a CLI home (symlink attack) | `cargo test -p harness-core worktree::symlinked_root_refused` |
| 4 | Remove refuses paths outside the managed root | `cargo test -p harness-core worktree::remove_outside_root_refused` |
| 4 | Created worktree contains no denied paths (no CLI home files copied in) | `cargo test -p harness-core worktree::no_denied_paths_in_tree` (plants a fake `.claude/` file in the source repo's history; asserts the worktree rejects it or the check fails closed) |
| 2 | Git runner passes no config-home variables | `cargo test -p harness-core worktree::env_has_no_config_home` |
| 1 | One worktree per task; second create refused | `cargo test -p harness-core worktree::one_per_task` |
| 9 | No worktree is created before the scheduler asks (no public auto-create) | `cargo test -p harness-core worktree::no_create_without_request` (source grep for module-level calls; the manager has no constructor that creates) |
