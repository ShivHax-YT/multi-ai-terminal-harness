# T-110: Command palette, keyboard map and cross-screen checks

Status: draft
Phase: 1   Model hint: sonnet
Depends on: T-102 to T-109 merged   Runs: wave 4, sequential after all screen briefs

## Goal
Make every screen reachable from the keyboard alone, move the ⌘K navigation items into a tested list, and prove after all screens merge that the UI-level guarantees hold on every route under every mock scenario. This brief fixes nothing in other screens. Defects go back to the owning brief.

## Design pre-flight (before code)
- **Screen goal:** Reach any screen from the keyboard, and find nothing in the palette that acts.
- **Primary action:** none. The palette is navigation only, and Enter opens the highlighted item. This brief adds no filled button.
- **Tokens:** `--popover` (palette surface), `--ring` (2px, offset 2px) on every interactive element, `--muted-foreground` for shortcut chips (full-round).
- **Wireframe, 1024 px** (palette centred, 480 px wide):
```
+------------------------------------------------+
| > Go to                                        |
|------------------------------------------------|
|  Providers                              Cmd 1  |
|  Lead                                   Cmd 2  |
|  Plans                                  Cmd 3  |
|  Sessions                               Cmd 4  |
|  Review                                 Cmd 5  |
|  Usage                                  Cmd 6  |
|  Settings                               Cmd 7  |
|  Theme: light / dark / system                  |
+------------------------------------------------+
```
- **Wireframe, 1440 px:** the same dialog at 560 px wide, centred over the content. The sidebar stays visible behind it.
- **Signature motion:** none. The palette uses shadcn Dialog's default fade and zoom only (transform and opacity, at most 150 ms). Static under reduced motion.
- **Inspiration technique borrowed:** Godly: right-aligned keyboard hint chips in list rows.
- **States:**
  - Empty: "No matches" when the filter has no result (`ready`).
  - Route checks: each route runs under `ready`, `fresh`, `errors`, `killswitch` and `rate_limited`. Each must render a heading and its loading and error states without crashing.

## Behaviour
- `items.ts` is a pure list: seven navigation items (Providers ⌘1 to Settings ⌘7) and the theme choice. Nothing else. Labels come from screen titles, never from provider names.
- Esc closes the palette and any dialog, and focus returns to the trigger. A route change moves focus to that page's H1.
- `docs/design/keyboard.md` is written from `items.ts` and the design README.
- The shell currently inlines the list (T-101). After merge, the lead switches the shell to `items.ts`. Until then, the `items.ts` test is the source of truth.
- The cross-screen checks import no feature module. They use `renderRoute` and the mock only, which keeps the zone rule intact.
