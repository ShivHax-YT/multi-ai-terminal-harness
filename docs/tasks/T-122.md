# T-122: Codex headless adapter (`codex exec --json`)

Status: draft
Phase: 1   Model hint: sonnet

## Goal
Implement the Codex adapter from T-120 by running the unmodified `codex` binary headless. It runs `codex exec --json`
per task, maps the JSON events by the mapping in `spike/normalize/codex.jq`, resumes a thread by ID, detects rate-limit
and usage errors, and reads auth status only from `codex login status` by exit code. It uses the default config and
login only: no profile, no config override, no sandbox bypass.

## Design
1. **Invocation.** `codex exec --json --sandbox workspace-write -C <worktree> <prompt>`, with the flag spelling from the
   T-003 capture. The sandbox default is `workspace-write` (ARCHITECTURE security notes). The adapter never passes
   `--dangerously-*`, `--approve-for-me`, `--oss`, `--local-provider`, `-c`/`--config`, or `-p`/`--profile` (T-003 banned
   list). Those are asserted in tests.
2. **Resume.** `codex exec resume <thread_id> --json <prompt>` from the same worktree. The flag placement for `-C` is
   the one T-003 recorded.
3. **Env.** Runner allowlist only. The adapter sets nothing; no config-home variable, no `CODEX_HOME`.
4. **Parse and map.** Items and events map by `spike/normalize/codex.jq`. Unknown types go to `unknown`. A final
   `result` must carry numeric usage tokens or the adapter emits `error`.
5. **Limits.** Rate-limit and usage-exhausted events become `rate_limited` with the shape in T-003's `EVENTS.md`
   (docs-sourced shapes are labeled). No retry in the adapter.
6. **Auth status.** `auth_status()` runs `codex login status` (T-001 preflight) and maps the exit code only. Output is
   discarded. Timeout 10 s, unknown on timeout.
7. **Login.** `login_argv()` returns the documented Codex login command as captured in T-003. The login runs in an
   app-owned interactive PTY (T-123), with the human completing it.
