# T-102: Providers screen (install, binary and sign-in status)

Status: draft
Phase: 1   Model hint: sonnet
Depends on: T-101 merged   Runs: wave 1, parallel with T-104 and T-106 (no shared files)

## Goal
Show, for each provider, whether its CLI is installed, binary-verified, signed in and usable as lead or worker, using only the status the backend reports. Offer the one next step. This screen reads no CLI files (rule 4). Sign-in happens in the CLI's own terminal, which the human completes.

## Design pre-flight (before code)
- **Screen goal:** Show what blocks each provider and the one next step.
- **Primary action (the only filled button, state-driven):** binary not verified: "Check again". Personal use unconfirmed: "Confirm it is my account". Signed out: "Sign in in terminal" (disabled until confirmed). Usable: "Go to Lead". Not installed: no filled button; the install text is copyable.
- **Tokens:** `--background`, `--card` (provider cards, solid), `--border`, `--foreground`, `--muted-foreground`, `--primary` (one button), `--success` / `--warning` / `--destructive` (always with icon and text), mono for version and path.
- **Wireframe, 1024 px** (sidebar as icon rail):
```
+--+------------------------------------------------+
|  | Providers                      [Cmd K] [Theme] |
|  | Each CLI runs on this Mac. You sign in.        |
|  | +--------------------+ +---------------------+ |
|  | | <ProviderName>     | | <ProviderName>      | |
|  | | [ok] installed     | | [x]  not installed  | |
|  | | [ok] verified      | | copy install text   | |
|  | | [!]  signed out    | |                     | |
|  | | [Sign in in term.] | |                     | |
|  | +--------------------+ +---------------------+ |
+--+------------------------------------------------+
```
- **Wireframe, 1440 px** (sidebar expanded, cards in a 3-column grid, content max 1200 px):
```
+----------+-------------------------------------------------------+
| Sidebar  | Providers                              [Cmd K] [Theme]|
| (240 px) | +-----------+ +-----------+ +-----------+             |
|          | |<Provider> | |<Provider> | |<Provider> |             |
|          | |status rows| |status rows| |status rows|             |
|          | +-----------+ +-----------+ +-----------+             |
+----------+-------------------------------------------------------+
```
- **Signature motion:** Stagger (Animated Group) on provider cards, once, at most 300 ms, 40 ms step. Nothing else animates.
- **Inspiration technique borrowed:** Dribbble onboarding checklist: one highlighted next step, the others quiet.
- **States (each rendered from a mock scenario and tested):**
  - Loading: `LoadingSkeleton` while `list_providers` is pending (`ready`, held promise).
  - Empty: `EmptyState` "Nothing is ready yet" when no provider is usable (`fresh`).
  - Error: `ErrorAlert` when a command rejects (`errors`). A refused login shows "Blocked by rule 6" (`binary_failed`).

## Behaviour
- Render `ProviderStatus` as the backend returns it. Never recompute `usable`. Map each `Blocker` to one plain sentence.
- Personal use is confirmed before sign-in is offered (rule 5).
- Sign-in runs `confirm_personal_use`, then `open_provider_login`, then navigates to `sessionPath(session_id)`. The session page belongs to T-105 and T-106. Do not import it.
- Gemini (`auth_modes: ["api_key"]`): no sign-in control. Show "API key only" and a secondary link to Settings.
- `killswitch: "disabled"` shows "Turned off by remote config" with no action. `api_key_only` shows "Subscription use is off. API key only."
- The install hint is `CopyButton` with mono text. Never a link.
- Do not auto-retry on `rule_blocked` or `rate_limited`.

## Notes / open questions
- **Install command:** `ProviderStatus` has only `install_hint`, with no install command. Rule 6 lets the app run a vendor installer after confirmation. v1 shows copy-only text. Request to the lead: decide whether an install command belongs in the contract, and when.
- **Shared status chip:** T-102, T-104, T-105 and T-107 each need icon-plus-label status. Request to the lead: add `StatusChip` to `src/components/common/` before wave 1.
- **Navigation:** the screen navigates after `open_provider_login` and never imports the sessions feature (zone rule).
- **Copy:** the install text is plain text. The copy must not name a provider as a literal (use `ProviderName`).
