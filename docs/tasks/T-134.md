## Design
1. **Wrapper.** The PTY runs this app's closed `--provider-session=<claude|codex>` mode. It owns the controlling terminal
   (setsid and TIOCSCTTY from portable-pty), launches the CLI through the kernel launch requirement, and hands it the
   foreground group, so Ctrl-C and SIGWINCH reach the CLI. Arguments are empty: no app or model text reaches the CLI.
2. **Identity.** A terminal requires the vendor team, identifier, Developer ID category and hardened runtime. It does not
   require the reviewed-release hash: the CLIs update themselves, and a new vendor-signed release is still the vendor's CLI.
3. **Status after an update.** When the pinned status probe is refused, status re-probes on the vendor identity alone and
   reports `binary.release_reviewed: false`. Tasks stay off. The pinned path and its tests are unchanged.
4. **Input.** `pty_write` refuses unless that session's take-over is on. One UI module sends input, only with a trusted user
   event in the same turn. xterm's replies to output queries are dropped (T-106 behaviour 2).
5. **Limits and consent.** Terminals count toward the 2-session ceiling per provider (T-123 decision). Rule 5: a terminal is
   refused until the human confirms the account is their own; the answer is in memory only and asked again after a restart.
6. **Folder.** Native panel or typed path, resolved through the file-access layer, which refuses credential stores (rule 4).
