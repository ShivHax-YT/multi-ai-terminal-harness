# T-112: Persisted per-provider usage store and pacing state

Status: approved by ShivHax-YT on 2026-10-25 (hands-off authorization; lead-approved)
Phase: 1   Model hint: sonnet
Depends on: T-111 merged   Runs: wave 2, after T-111 (sequential; shares the `limits` types)

## Goal
Persist the per-provider counters that rule 2 requires to survive restarts, sign-out and account switches. Counters
belong to the provider on this machine, so the store has no account or session key at all. Also persist the pacing
state (consecutive limit errors, backoff end, pause) so a restart cannot clear a pause (rule 10). Nothing in this
brief resets a counter on an event; counters only age out of their rolling windows.

## Design
1. **Storage.** SQLite (ARCHITECTURE.md: "usage store (SQLite)") via `rusqlite` with the bundled feature. One database
   file at the caller-supplied location. Tables: `prompt_events(provider, at)`, `turn_counts(task_id, provider, n)`,
   `run_minutes(provider, day_utc, minutes)`, `tokens(provider, day_utc, input, output, is_estimate)`,
   `pacing(provider, consecutive_limit_errors, backoff_until, attempt, paused, paused_until)`.
   There is no column named `account`, `profile`, `session` or `login` (test: schema introspection).
2. **Keys.** Every row is keyed by `ProviderId` (from `src/strings/providers.ts` mirrored as a Rust enum in this crate's
   `usage::ProviderKey`). The string set is exactly `claude, codex, grok, kimi, gemini, glm`.
3. **Writes.** Every admitted prompt and every run-minute tick writes through a single `UsageStore` method. Writes are
   in transactions. A failed write refuses the prompt (fail closed), it never silently drops a count.
4. **Reads.** `snapshot(now) -> UsageSnapshot` builds the contract type. Meters carry `current`, `limit` (the user's
   stricter value when set, else the ceiling) and `ceiling`. `tokens_today` is marked `is_estimate: true` for
   subscription providers. `spend` is `null` in Phase 1 (API-key providers are Phase 3).
5. **No reset API.** The module exposes no `reset`, `clear`, `forget` or `delete_provider` function. Rolling windows
   age rows out by query (`at > now - 60 min`); daily values are read by `day_utc = today`. A test greps the module
   source for those names.
6. **Pacing persistence.** `save_pacing` / `load_pacing` for the record above. A paused provider stays paused after a
   restart until its `paused_until` passes or `resume_provider` is called (the resume path lives in T-131).
7. **Corruption.** If the database cannot be opened or fails an integrity check, the store refuses to start and the app
   shows an error. It never recreates an empty database, because that would reset counters (rule 2).

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 2 | Counters per provider only; survive restart; unchanged by sign-out or account switch (no account key exists) | `cargo test -p harness-core usage::counters_survive_restart`, `usage::sign_out_does_not_reset`, `usage::account_switch_does_not_reset` (the last two call the public API that a status change would use and assert identical snapshots) |

| 10 | Pause and backoff survive a restart | `cargo test -p harness-core usage::pause_survives_restart` |
| 1 | Snapshot meters show the stricter limit and the ceiling | `cargo test -p harness-core usage::snapshot_meters` |
