# T-115: Binary verifier (pinned signer, codesign, checksum, install source)

Status: approved by ShivHax-YT on 2026-10-25 (hands-off authorization; lead-approved)
Phase: 1   Model hint: sonnet
Depends on: T-114 merged (the narrow binary-path exception in `fs_guard`)   Runs: wave 3, after T-114

## Goal
Port T-001's preflight to Rust as the app's binary verifier. Before any automation, and again on each startup and each
version change, check the CLI binary: macOS code signature (`codesign --verify --strict`) and that the signer matches
a pinned identity, the vendor checksum where one is published, and that the install path came from the official source.
Record the version and the results. A binary that fails any applicable check is refused for automation and the
provider falls back to view-only.

## Design
1. **Resolution.** `resolve(provider) -> ResolvedBinary { path, via }` looks up the official install locations listed in
   `vendor-pins.toml` (absolute paths only; no PATH search for trust decisions). Symlinks are resolved once, and the
   final target is what gets checked. The verifier calls `fs_guard::exec_resolve`, never opens the directory.
2. **Codesign check.** Run `/usr/bin/codesign --verify --strict --verbose=4 <path>` with a 10 s timeout, then
   `/usr/bin/codesign -d --verbose=4 <path>` and parse `TeamIdentifier` and `Authority`. Pass only when verification
   exits 0 and the TeamIdentifier equals the pinned value for that provider. "Not signed" and "not a Mach-O" are
   recorded as `fail` with the message, never silently passed.
3. **Checksum.** Where `vendor-pins.toml` lists a published SHA-256 for a version, compare it (`sha2`). Where none is
   published, the check is `not_applicable`. The contract allows that.
4. **Install source.** The resolved path must match an allowed prefix from `vendor-pins.toml`. A binary found only in
   an unlisted location (for example a user-writable temp folder) fails `install_source`.
5. **Version and re-check.** Run `<path> --version` (the one permitted argument) with a timeout and store the version.
   Re-run all checks when the version or the file's mtime+size changes. Any failure sets `binary.state = "failed"`
   and the adapters refuse to start automation. Verification never caches a pass across a version change.
6. **Output.** `BinaryReport` maps directly onto `ProviderStatus.binary` and `install` in the contract (checks list,
   `checked_at`, `state`). Detail strings must not include any path under a denied directory.

## Notes / open questions
- **Human decision: pinned identities.** The TeamIdentifier values for Anthropic and OpenAI, and any vendor-published
  checksum URLs, are not known to this brief. The human (or the lead after checking the vendors' own docs) fills
  `compliance/vendor-pins.toml`. Until then, both providers report `binary.state = "unchecked"` and no automation starts.
- T-001's preflight does not pin a signer; it only records the codesign result. This brief adds the pin, which is the
  "pinned-signer" part of the port.
- Linux CI cannot run `codesign`. Non-macOS builds fail closed (`binary_unchecked`), and the macOS-only tests are gated.
