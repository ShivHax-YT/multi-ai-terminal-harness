# T-124: Session manager (worker and login session state, start, pause, resume, kill)

Status: proposed (the hands-off approval of 2026-10-25, commit deb08f4, was revoked by ShivHax-YT on 2026-10-26; only the human approves)

Depends on: T-111 (permits, events), T-113 (pacing), T-118 (worktrees), T-119 (runner), T-120 (adapter trait and state table)   Runs: wave 7

## Goal
Hold the state of every worker and login session and move it through T-004's state machine. The session manager starts
an admitted session (it takes a permit from `limits`, asks `pacing`, creates the worktree, and starts the adapter via
the runner), tracks turns and pause reasons, and publishes `SessionView` snapshots as events. It creates no PTY: a
terminal for a session is attached by the app crate through `pty-view` (T-131), because harness-core must not depend on
`pty-view` (rule 3).

## Design
1. **Start.** `SessionManager::start(req: StartRequest { kind: Worker | Login, provider, task_id?, plan_id?, worktree? })`.
   Order is fixed and tested: (a) `limits.acquire_session` (refuse at 2); (b) `pacing.check_dispatch` for workers;
   (c) `worktree.create` for workers; (d) `runner.spawn` via the adapter; (e) publish `session_changed`. A refusal at any
   step releases earlier resources. Login sessions take a permit and skip (b) and (c).
2. **Turns.** Each `result` or `message` boundary that the adapter reports as one turn calls `limits.record_turn`. The
   41st turn is refused and the session is paused with reason `ceiling`.
3. **States.** `spawning -> running <-> idle -> exited | killed`, and `rate_limited` when an invocation ENDS after a
   `rate_limited` event was seen in it (counted once per invocation; T-004 state machine, per-invocation flag; pacing
   records it). Transitions go through T-120's pure table. Illegal transitions are errors.
4. **Pause and resume.** `pause(session, reason)` (user, user_idle, app_background, takeover, limit_errors, ceiling,
   spend_cap, killswitch). `resume(session)` is refused with rule 10 during backoff and with rule 1 at a ceiling; it
   never resumes a `killed` or `exited` session. Resume starts the next invocation with `--resume` semantics via the
   adapter's `send` (headless) and never writes into a live child.
5. **Takeover flag.** `set_takeover(session, enabled)` records the flag and pauses automation with reason `takeover`
   when enabled. Disabling leaves the session paused until an explicit resume. The flag is read by the app's input gate
   (T-131); this module never writes input.
6. **Kill.** `kill(session)` calls the runner's cancel with a grace period, releases the permit on exit, and sets
   `killed`. Worktree files stay (the screen copy says so).
7. **Snapshots.** Every change publishes a full `SessionView` through `EventSink` (`session_changed`). Consumers replace
   their copy; no deltas.
8. **Idle and background.** Presence changes arrive as `Presence` input from the app (T-111). Idle >= 30 min or background
   pauses every worker with the matching reason. Login sessions are exempt from idle pause.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 1 | Third concurrent session refused; ceiling pause at 41st turn; idle pause | `cargo test -p harness-core session::concurrency_ceiling`, `session::turn_ceiling_pauses`, `session::idle_pauses_workers` |
