## Goal
Be the only path from an approved plan to a running worker. The scheduler accepts a plan only with a valid approval
token for its exact hash (T-117), re-runs the plan checker (T-116), asks limits and pacing before each dispatch,
dispatches one worker at a time in Phase 1, and refuses any failover that is not to a different provider listed in the
approved plan. It has no timer and no cron for subscription providers. It is driven by explicit calls from the lead
loop and the app. The 24-hour simulated-clock test (rule 1) proves subscription activity stops at the daily ceiling and
on user idle.

## Design
1. **Accept.** `Scheduler::accept(plan_bytes, token, presence)`: parse once (T-116), run the checker in scheduler mode,
   verify the token (T-117). Any failure returns a refusal and nothing is stored as runnable.
2. **Dispatch one.** `Scheduler::dispatch_next(now)`: picks the next task whose `depends_on` are done, one active worker
   at a time. Before the session starts it checks, in order: presence (idle < 30 min, app in foreground for workers),
   `limits` (prompt window, run-minutes, concurrency), and `pacing.check_dispatch`. Any refusal returns the reason and
   no session starts.
3. **Failover guard.** `failover::may_fail_over(from, to, plan)` refuses when `to == from`, when `to` is not a
   `provider` of some task in the approved plan, or when `to` appears twice in the chain. Phase 1 has no failover
   execution; the guard exists and is tested now (BUILD_PLAN Phase 1 tests), so Phase 3 cannot skip it.
4. **Same-provider rule.** A limit error on provider P never produces a dispatch to P for the same task, even after the
   backoff window; it only produces a pause. The failover guard is the only place that could move work.
5. **Ticks, not timers.** `tick(now, presence)` is called by the lead loop and by the app on user action. The module
   contains no `sleep`, `interval`, `cron`, or `spawn` of a background loop. Subscription providers have no unattended
   path at all (rule 1).
6. **Ceiling checks at dispatch.** The scheduler re-checks the ceilings at dispatch even though the plan checker already
   did (plan.md: "the scheduler enforces the same ceilings at dispatch regardless of what a plan says").
7. **Stop conditions.** A task that reaches 40 turns pauses with reason `ceiling` and waits for the user.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 1 | Unattended or scheduled subscription run refused; no timer API in the module | `cargo test -p harness-core scheduler::no_timer_api` (greps for `sleep`, `interval`, `cron`, `tokio::time`, `spawn(`) and `scheduler::unattended_subscription_refused` |
| 1 | 24-hour simulated clock: subscription activity stops at the daily run-minute ceiling and on idle | `cargo test -p harness-core --test sim_24h` (advances `SimClock` in 1-minute steps for 24 h; asserts activity ends at 480 run-minutes, no dispatch while idle, and no dispatch after the ceiling until the next UTC day) |
| 1 | Prompt and turn ceilings enforced at dispatch | `cargo test -p harness-core scheduler::ceilings_rechecked_at_dispatch` |
| 9 | Unapproved, edited or mismatched plan never runs | `cargo test -p harness-core scheduler::refuses_unapproved`, `scheduler::refuses_edited` |
| 9 | Failover only to a provider listed in the approved plan | `cargo test -p harness-core scheduler::failover_outside_plan_blocked` |
| 2 | Chain listing the same provider twice is rejected | `cargo test -p harness-core scheduler::failover_duplicate_rejected` |
| 2 | Failover to the provider that hit its limit is rejected | `cargo test -p harness-core scheduler::failover_same_provider_rejected` |
| 2 | A limit error never triggers a new session on the same provider | `cargo test -p harness-core scheduler::limit_error_no_same_provider_session` |
| 10 | No dispatch within 5 s of the last one for a provider; backoff respected | `cargo test -p harness-core scheduler::pacing_respected` |
| 3 | No PTY symbol or dependency | `make crate-boundary` and `cargo test -p harness-core scheduler::no_pty_symbols` |
