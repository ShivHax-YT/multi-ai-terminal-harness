# T-119: Headless child process runner (process groups, kill, env allowlist)

Status: approved by ShivHax-YT on 2026-10-25 (hands-off authorization; lead-approved)
Phase: 1   Model hint: opus (signals, process groups, concurrency; one opus writer at a time)
Depends on: T-101 merged   Runs: wave 5, alone as the only opus writer (not alongside T-106 or T-123)

## Goal
Spawn a headless provider CLI (`claude -p`, `codex exec`) with piped stdout and stderr, read its JSONL line by line, and
stop it reliably. Each child gets its own process group. Cancel sends SIGTERM to the group, then SIGKILL after a grace
period. Dropping the handle kills the group. The child receives only an allowlisted environment. After spawn, the
handle exposes no way to write to the child's stdin (rule 3): the prompt goes in as the CLI's documented argument, and
stdin is closed at spawn.

## Design
1. **Spawn.** `spawn(SpawnSpec { argv: Vec<OsString>, cwd, env: EnvPolicy, stdin_once: Option<Vec<u8>> }) ->
   Result<HeadlessChild, SpawnError>`. `argv[0]` must be an absolute path (from the binary verifier, T-115). `cwd` must
   be an existing directory. The child is started with `process_group(0)` so it leads its own group.
2. **No stdin API.** `HeadlessChild` has no `write`, `stdin` or `send` method. `stdin_once`, if used at all, is written
   once during `spawn` and then the pipe is closed. A compile-time test checks that the handle type has no stdin
   accessor (see the rule 3 row).
3. **Env allowlist.** `EnvPolicy` starts from empty. It adds `PATH` (fixed safe value), `HOME` (the caller's, unchanged),
   `LANG=C.UTF-8`, `TERM=dumb`, `NO_COLOR=1`. Anything else must be listed explicitly by the adapter. The policy rejects
   `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GROK_HOME`, `KIMI_CODE_HOME` at construction (rule 2) and any name matching
   `*_API_KEY` or `*_TOKEN` unless an adapter explicitly lists it (Phase 3 only).
4. **Lines.** `next_line().await` yields complete JSONL lines with a 4 MiB maximum line length. A longer line is
   reported as an error event and the reader keeps draining (never buffer unbounded). Stderr is captured into a
   bounded ring (64 KiB) and never logged verbatim.
5. **Cancel.** `cancel(grace: Duration)`: `killpg(pgid, SIGTERM)`, wait up to `grace`, then `killpg(pgid, SIGKILL)`.
   Reap the leader with `wait`. Exit status is reported as `exited{code?, signal?}`.
6. **Drop.** `Drop` performs the same SIGKILL path for the group if the child is still running. A child that spawns
   grandchildren leaves none behind (the group kill covers them).
7. **Unsafe.** Any `unsafe` block (for `libc::killpg` and `setpgid` if not covered by std) needs a `// SAFETY:` comment
   and a unit test. The brief prefers `std::os::unix::process::CommandExt::process_group` plus `libc::killpg`.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 3 | No write path to the child after spawn; stdin closed | `cargo test -p harness-core process::handle_has_no_stdin` (compile-fail doctest on `HeadlessChild::stdin`) and `process::stdin_closed_after_spawn` (a fixture that reads stdin reports EOF immediately) |
| 2 | Config-home variables refused by the env policy | `cargo test -p harness-core process::env_refuses_config_homes` |
| 4 | Child env contains only the allowlist (no inherited secrets) | `cargo test -p harness-core process::env_is_allowlist_only` (sets a fake `SECRET_TEST_VAR` in the parent; the child's `env` output lacks it) |
| 1 | Runs only for a session the caller already admitted (no timers in this crate) | `cargo test -p harness-core process::no_timers` (greps the module for `interval`, `sleep_until`, `cron`) |
| 10 | Cancel and kill never restart a child | `cargo test -p harness-core process::no_restart` |

Also run: `cargo test -p harness-core process::cancel_kills_group` (fixture spawns a grandchild that ignores SIGTERM;
after cancel, neither process is alive) and `process::drop_kills_group`.
