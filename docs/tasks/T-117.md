# T-117: Approval token: minted only by the approve command, verified by the scheduler

Status: proposed (the hands-off approval of 2026-10-25, commit deb08f4, was revoked by ShivHax-YT on 2026-10-26; only the human approves)
Phase: 1   Model hint: sonnet
Depends on: T-116 merged (plan parse, hash, checker), T-101 merged (`approve_plan` stub, `stub_never_approves` test)   Runs: wave 2, parallel with T-112 and T-118

## Goal
Implement rule 9's binding. A token is created only inside the `approve_plan` command handler, after the UI click, and
only when the plan's hash matches the one the user saw and the checker reports no violations. The token is signed with
a per-install Ed25519 key kept in the macOS Keychain under the app's own item. The harness-core side only verifies. The
scheduler accepts a plan only with a valid token for that exact hash. Nothing else in the workspace can build one.

## Design
1. **Token shape.** `{ plan_hash, approved_at, approved_via: "ui", nonce, signature }` where `signature` is Ed25519 over
   the canonical bytes of `{plan_hash, approved_at, approved_via, nonce}`. `nonce` is at least 16 random characters
   from the OS RNG (`getrandom`).
2. **Mint (app crate only).** `approve_plan({plan_id, plan_hash})`:
   a. load the stored plan bytes for `plan_id`, parse once (T-116), compute the hash;
   b. if the hash differs from the argument, return `plan_hash_mismatch`;
   c. if the checker reports violations, return `plan_has_violations`;
   d. sign with the per-install key and store the token on the plan record; return `PlanView`.
   The signing key is loaded from the app's Keychain item at first use and generated once if absent. Its private part
   never leaves `commands/approval.rs`.
3. **Verify (harness-core).** `verify_for_dispatch(parsed_plan, token, public_key) -> Result<(), ApprovalError>`. Checks:
   hash equals the recomputed hash; `approved_via == "ui"`; signature valid; `approved_at` parses; nonce length >= 16.
   Missing token, a token from another plan and a stale token (after any edit) all fail.
4. **Replay.** `NonceLedger` (in-memory, per process) refuses a nonce already used for a dispatch. Phase 1 scope:
   in-memory; a restart clears replay memory, but the hash binding still stops reuse of an edited plan. Note the decision.
5. **Edits void approval.** `update_plan` (T-131 wiring) returns a new hash and clears the token. This brief adds
   `invalidate(plan_id)` used by that path and a test that an edit followed by dispatch is refused.
6. **Public key.** The verifier receives the public key by parameter. harness-core holds no signing code: no `sign`,
   `SigningKey` or `keyring` import anywhere in the crate (tested by grep).
