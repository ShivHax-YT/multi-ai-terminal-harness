# T-107: Review (diff, test log, handoff, summary)

Status: proposed (the hands-off approval of 2026-10-25, commit deb08f4, was revoked by ShivHax-YT on 2026-10-26; only the human approves)
Phase: 1   Model hint: sonnet
Depends on: T-101 merged   Runs: wave 2, parallel with T-103 and T-105 (no shared files)

## Goal
Let the human read one task's diff, test log and handoff, see the lead's summary against its token budget, and mark the task reviewed. Everything a worker, CLI or the lead produced is untrusted, so it renders as text only.

## Design pre-flight (before code)
- **Screen goal:** Check what the worker changed and whether it passed, then mark it reviewed.
- **Primary action:** "Mark reviewed" (filled) when the state is `ready`. No filled button when `running`, `reviewed` or `failed`.
- **Tokens:** `--card` (summary and tab panel), `--muted` (diff and log surface). Test status uses `--success` / `--warning` / `--destructive` with icon and text: "Passed", "Failed", "Not run". Diff lines carry `+` and `-` prefixes, with tints from the status tokens. Mono 13px for diff, logs and paths.
- **Typography:** H1 task title 24px. Summary body 16px at about 65ch. Token count 14px muted ("142 of 200 tokens").
- **Wireframe, 1024 px** (list above detail, stacked):
```
+--------------------------------------------------+
| Review                                           |
| t1 Add theme tokens  <ProviderName>  ready       |
| [Diff] [Tests] [Handoff]       [Mark reviewed]   |
| +----------------------------------------------+ |
| | +  --primary: #9C1F6E;                       | |
| | -  --primary: #000;                          | |
| +----------------------------------------------+ |
| Summary (142 of 200 tokens)                      |
| Added dark tokens. Tests pass.                   |
+--------------------------------------------------+
```
- **Wireframe, 1440 px** (task list 320 px on the left, detail on the right):
```
+----------+-------------------------------------------------------------+
| Sidebar  | Tasks      | t1 Add theme tokens        [Mark reviewed]   |
| (240 px) | > t1 ready | [Diff] [Tests] [Handoff]                     |
|          |   t2 run   | diff block (scrolls)                         |
|          |            | Summary (142 of 200 tokens)                  |
+----------+-------------------------------------------------------------+
```
- **Signature motion:** Transition Panel (PanelSwitch) between Diff, Tests and Handoff, at most 250 ms.
- **Inspiration technique borrowed:** Dribbble code-review tag: a list and detail pair with a sticky header.
- **States:**
  - Loading: `LoadingSkeleton` while `get_review` is pending (`review_ready`).
  - Empty: "Nothing to review yet. Tasks appear here when a worker finishes." (`running`, no ready task).
  - Injection: hostile HANDOFF, diff and log text render as text (`review_injection`).
  - Handoff error: `ErrorAlert` on the Handoff tab with the untrusted error text. The other tabs still work (`review_handoff_error`).
  - Error: `ErrorAlert` (`errors`).

## Behaviour
- **Diff:** `diff.text` in a pre-wrap mono block inside `ScrollArea`. If `truncated`, show "The backend truncated this diff." No diff-to-HTML library (T-101 bans diff2html).
- **Tests:** status reads "Passed", "Failed" or "Not run". "Not run" is a warning, never success.
- **Summary:** `UntrustedText`. The token count comes from `lead_summary.tokens` and `budget`. Over budget shows a warning in text. The UI does not count tokens.
- **Links:** in-app tab links built with `reviewPath(taskId, tab)`. Never URLs, and no auto-linked text.
- **Handoff:** shown field by field, as text.
- **Mark reviewed** calls `mark_reviewed`. Update the view from the returned `ReviewView`.
