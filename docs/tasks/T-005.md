## Goal
Define the plan the lead produces and the user approves (docs/ARCHITECTURE.md "How the lead works"), how a plan is
hashed, and how an approval token binds to that hash so any edit invalidates it (rule 9). Prove it with a small
offline checker.

## Design
- Plan fields: `plan_id`, `created_at`, `lead {provider}`, `request_summary`, `summary_budget_tokens` (default 200),
  `tasks[]`: `{id, title, role, provider, auth_mode (subscription|api_key), owned_files[], acceptance[],
  depends_on[], estimated_usage {prompts, turns}, fallback_providers[]}`, and an optional `approval`.
- Hash: canonical JSON of the plan **without** `approval` = `jq -S -c 'del(.approval)'`, then `shasum -a 256`.
  `plan.md` notes that the app will use RFC 8785 (JCS) canonicalization and why the spike's form is close enough.
- Approval token: `{plan_hash, approved_at, approved_via: "ui", nonce}`. In the app it's signed with a per-install key
  in the Keychain and created only by a UI click; the spike only proves the binding.
- `check.jq` rejects a plan where:
  - a task's `fallback_providers` contains its own `provider` or repeats one (rule 2);
  - a fallback provider isn't used anywhere in the plan (rule 9);
  - a `gemini` task has `auth_mode` other than `api_key` (rule 7);
  - a task's `estimated_usage.turns` > 40, or a subscription provider's summed `prompts` > 30 (rule 1, so the UI can
    warn before approval);
  - `approval.plan_hash` is present but doesn't match the computed hash (rule 9).
- Examples: `plan-valid.json`, `plan-dup-fallback.json`, `plan-gemini-subscription.json`, `plan-over-turns.json`,
  `plan-stale-approval.json` (approved, then a task edited).

## Hard rules touched
| Rule | How | Test |
|---|---|---|
| 9 | Approval bound to the plan hash; any edit invalidates it | test: edit one field of an approved plan → rejected |
| 2 | Fallback never the same provider, no repeats | test: `plan-dup-fallback.json` rejected |
| 7 | Gemini only with api_key | test: `plan-gemini-subscription.json` rejected |
| 1 | Turn/prompt estimates checked against the ceilings | test: `plan-over-turns.json` rejected |
