Status: approved by ShivHax-YT on 2026-10-25 (hands-off authorization; lead-approved)

Depends on: T-115 (binary), T-120 (registry), T-121 and T-122 (auth status), T-123 (login PTY), T-128 (kill switch)   Runs: wave 9, after T-123

## Goal
Replace the T-101 stubs for `list_providers`, `refresh_provider_status`, `confirm_personal_use` and `open_provider_login`
with real backend answers. The backend computes `ProviderStatus`, including `usable` and its blockers, from the binary
check, the adapter's documented auth status, the kill switch and the personal-use confirmation. The UI never recomputes
it. Sign-in happens only in the CLI's own login inside an app-owned terminal that the human completes.

## Design
1. **Assembly.** `status::assemble(provider, binary_report, auth, killswitch, personal_use, api_key) -> ProviderStatus`.
   `usable.lead` and `usable.worker` are computed here and only here. A provider is usable as worker when: adapter
   registered, binary verified, signed in (subscription), personal use confirmed, killswitch enabled, not paused by
   limits. Each unmet condition adds one `Blocker` from the contract.
2. **Auth.** `sign_in.state` comes from the adapter's `auth_status()` (exit code only). `unknown` maps to
   `sign_in_unknown`. The adapter's output is never read.
3. **list / refresh.** `list_providers` returns the cached assembly. `refresh_provider_status` reruns the binary check
   (T-115) and the adapter's auth status, then returns and emits `provider_changed`.
4. **Personal use.** `confirm_personal_use(provider)` records a timestamped confirmation in the app settings store
   (T-127 owns the store; this brief calls it). It does not change any counter.
5. **Open login.** `open_provider_login(provider)` checks in this order and refuses at the first failure:
   a. Gemini: `rule_blocked` 7 (Gemini is API key only; no subscription login path exists);
   b. binary failed or unchecked: `rule_blocked` 6;
   c. killswitch disabled, or api_key_only for a subscription mode: the matching blocker, no login;
   d. personal use not confirmed: `rule_blocked` 5;
   e. otherwise start the adapter's `login_argv()` through the app's PTY bridge as a `login` session with takeover on,
      and return `{ session_id }`. The session is created through T-124's manager.
6. **No login automation.** Nothing in this module types into the login. The human's keystrokes reach the PTY only
   through T-131's gated `pty_write`.
7. **Errors.** Every refusal is an `IpcError` with the contract kind and rule number. No refusal is retried.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 4 | Status comes only from documented status commands; no file reads | `cargo test -p harness-core status::no_fs_access` and `cargo test -p app providers::auth_from_adapter_only` |
