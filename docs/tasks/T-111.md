Status: draft

## Goal
Give the backend one injectable clock, one event sink and the in-memory enforcement of the rule 1 ceilings:
concurrent-session permits, 30 prompts per rolling hour, 40 turns per task, 480 run-minutes per day, and the 30-minute
idle presence rule. Pure logic, no file or network I/O. Everything later (usage store, pacing, scheduler, the 24-hour
simulated-clock test) runs on these types with a simulated clock.

## Design
1. **Clock.** `trait Clock { fn now(&self) -> DateTime<Utc>; fn monotonic(&self) -> Duration }`. `SimClock` is
   advanced only by `advance(Duration)`. No code in this crate calls `SystemTime::now()` or `Instant::now()` directly.
2. **Permits.** `ProviderLimits::acquire_session(provider) -> Result<SessionPermit, Refusal>`. `SessionPermit` is RAII:
   dropping it releases the slot. A third concurrent permit for one subscription provider is refused (rule 1, ceiling 2).
3. **Prompt window.** `admit_prompt(provider, task_id)` records a timestamp into a rolling one-hour window per provider.
   The 31st admission inside any 60 minutes is refused with `retry_at` = oldest timestamp + 60 min. Refusals never
   record a prompt.
4. **Turns.** `record_turn(task_id)` counts per task. The 41st turn is refused. Counts are per task id, not per session.
5. **Run time.** `run_started(provider)` / `run_stopped(provider)` accumulate automated minutes in a calendar day (UTC
   midnight reset of this counter only; see note). Crossing 480 minutes refuses `run_started` and any `admit_prompt`.
6. **Presence.** `Presence { idle_minutes, app_in_background }` is input supplied by the app. If idle >= 30 or the app
   is in the background, `admit_prompt` and `run_started` are refused with a reason. Presence is never inferred here.
7. **Refusal type.** `Refusal { rule: u8, kind: CeilingKind, message: String, retry_at: Option<DateTime<Utc>> }`,
   mapped by the app to `IpcError{kind: "rule_blocked", rule}`.
8. **Ceilings are read, never configured.** Every limit comes from `compliance::ceilings`. The type has no constructor
   that takes a number. A user limit (stricter) is a separate value passed in, and `min(user, ceiling)` is the only
   combination allowed, so a looser user value cannot be applied here.

Note: the daily run-minute counter's persistence is T-112's job. This brief keeps it in memory with an injected
`load`/`snapshot` pair so T-112 can persist it without a schema of its own.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 1 | Concurrency, prompts/hour, turns/task, run-minutes/day, idle 30 min all refused at the ceiling | `cargo test -p harness-core limits::` (`third_session_refused`, `thirty_first_prompt_refused_within_hour`, `forty_first_turn_refused`, `run_minutes_capped_at_480`, `idle_30_blocks_prompts`) |
| 1 | No code path builds a limit above the ceiling | `cargo test -p harness-core limits::user_limit_cannot_loosen` (passing 99 is clamped to the ceiling) |
| 1 | Subscription-only refusal of scheduled work: no timer or cron type in the module | `cargo test -p harness-core limits::no_timer_api` (greps the module source for `interval`, `cron`, `schedule`, `tokio::time`) |
