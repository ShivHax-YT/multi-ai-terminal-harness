## Goal
Implement the T-004 adapter interface in Rust as traits and types, the closed transport enum (`headless | acp` only, rule
3), the registry that refuses an adapter without a headless or ACP transport, the normalized event type that mirrors
`event.schema.json`, and the state the registry reads from the kill switch. The Claude and Codex adapters (T-121, T-122)
implement these traits. This brief contains no CLI-specific code.

## Design
1. **Transport.** `enum Transport { Headless, Acp }` with serde `rename_all = "lowercase"`. There is no `Pty` variant,
   and deserializing `"pty"` fails. A test asserts the variant set equals `["headless","acp"]`, matching T-004.
2. **Trait.** `trait Adapter: Send + Sync` with: `provider() -> ProviderId`, `capabilities() -> Capabilities { transport,
   resume, mcp, hooks }`, `start(&self, task, worktree) -> Result<SessionId, AdapterError>`, `send(&self, prompt)`
   (headless only: starts the next invocation with resume, never writes into a live child), `events()` (a stream of
   `NormalizedEvent`), `cancel()`, `auth_status() -> AuthStatus` (SignedIn | SignedOut | Unknown, from the CLI's
   documented status command only), `usage() -> UsageReport`, and `login_argv() -> Option<Vec<String>>`.
   `login_argv` is an addition to T-004's interface; see Notes.
3. **Registry.** `AdapterRegistry::register(adapter, killswitch_state)`. Registration fails when the capabilities report
   no `Headless` or `Acp` transport (rule 3). A provider whose killswitch state is `disabled` registers as unavailable
   (`adapter_available = false`, reason in the status). `api_key_only` registers but refuses subscription auth modes.
4. **Gemini.** The registry refuses to register a Gemini adapter unless its only auth mode is `api_key` (rule 7). The
   Gemini adapter itself is Phase 3; the rule is enforced now so the registry cannot be bypassed later.
5. **Normalized events.** `NormalizedEvent` is a tagged enum with the variants of `event.schema.json`:
   `session_started`, `message`, `tool_call`, `tool_result`, `result` (with numeric `tokens`), `rate_limited`, `error`,
   `exited`, `unknown`. Every variant carries `provider` and `ts`. `unknown` keeps `raw_type`; nothing is dropped.
6. **Session state table.** `SessionState` mirrors T-004's machine (`spawning`, `running`, `idle`, `rate_limited`,
   `exited`, `killed`) with the transition table as a pure `fn transition(state, event) -> Result<State, Illegal>`.
   T-124 uses this table; this brief tests it.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 3 | Closed transport enum without pty; registry rejects no-transport adapters | `cargo test -p harness-core adapters::transport_is_headless_or_acp`, `adapters::registry_rejects_no_transport` (a test adapter returning an empty capability set) |

| 12 | Disabled killswitch state keeps the adapter unavailable | `cargo test -p harness-core adapters::killswitch_disables_at_registration` |
| 10 | `rate_limited` carries reset or retry-after when present | `cargo test -p harness-core adapters::rate_limited_fields` |
