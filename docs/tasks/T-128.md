# T-128: Signed kill-switch config verifier (rule 12, Phase 1 local source)

Status: draft
Phase: 1   Model hint: sonnet
Depends on: T-101 merged (contract `KillSwitchStatus`); T-114 merged (file access)   Runs: wave 7, parallel with T-124

## Goal
Verify a signed remote configuration that can disable any adapter or force it to API-key-only, and apply it at launch.
An unsigned or badly signed config is ignored. If no new config can be read, the last known good config stays in force.
Phase 1 reads the config from a local file in the app data directory (the signed file is placed there by the human or a
test). Network fetching is Phase 4 and is not built here, so this brief opens no network connection.

## Design
1. **Format.** A JSON envelope `{ payload: {...}, signature: "<base64 Ed25519 over canonical payload bytes>" }`. The
   payload carries `issued_at`, `expires_at` (optional), and `adapters: [{provider, state: enabled|disabled|api_key_only,
   reason?}]`. Canonical bytes use the JCS subset from T-116 (sorted keys, no floats).
2. **Verify.** `verify(envelope, public_key) -> Verdict`. Valid signature and not expired: `Valid`. Bad or missing
   signature: `InvalidIgnored` (rule 12 "an unsigned config is ignored"). Malformed JSON: `InvalidIgnored`.
3. **Apply.** On launch: if the candidate verifies, it replaces the stored last-known-good config and applies. If not,
   the stored last-known config stays in force. With no stored config, every provider is `enabled` only if the rest of
   the app allows it, and the status reads `signature: absent`.
4. **Downgrade-safe.** A config with an older `issued_at` than the stored one is ignored (no rollback to a looser state).
5. **Effects.** `KillSwitchStatus { source, fetched_at, signature, adapters }` feeds the adapter registry (T-120) and
   `ProviderStatus.killswitch`. `disabled` removes the adapter from automation at the next launch (ceiling of "within
   one launch").
6. **No override.** No command sets a killswitch state. `get_killswitch_status` is read-only.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 12 | Signed config disables an adapter within one launch | `cargo test -p harness-core killswitch::signed_disable_applies_at_launch` (registry test with a valid config) |
| 12 | Unsigned or wrongly signed config is ignored | `cargo test -p harness-core killswitch::unsigned_ignored`, `killswitch::bad_signature_ignored` |

| 4 | Config file read through `fs_guard`, never a CLI home | `cargo test -p harness-core killswitch::reads_via_fs_guard` |
