# T-105: Sessions list and session state

Status: draft
Phase: 1   Model hint: sonnet
Depends on: T-101 merged   Runs: wave 2, parallel with T-103 and T-107 (T-106 owns the terminal folder beside it)

## Goal
List every worker and login session with its state, why it is paused and its retry time. Let the human pause, resume or stop one. The detail route embeds `SessionTerminal` from T-106 and shows the state read-only. Take-over and automation control belong to T-106 and the backend.

## Design pre-flight (before code)
- **Screen goal:** See what each session is doing, and why it is waiting.
- **Primary action:** "Resume" (filled) on a selected paused session. Otherwise no filled button. "Stop" is outline and opens an AlertDialog.
- **Tokens:** `--card` rows, `--foreground`, `--muted-foreground`. State chips carry icon and text. `--warning` for paused and rate limited. `--destructive` for exited with an error and for killed. Mono for branch and worktree.
- **Wireframe, 1024 px** (list route, rail sidebar):
```
+--+-------------------------------------------------+
|  | Sessions                                        |
|  | 1 running. Concurrent limit: 2.                 |
|  | +---------------------------------------------+ |
|  | | [>] running   Worker  <ProviderName>  t1    | |
|  | |     feat/dark-mode   turns 12 of 40         | |
|  | +---------------------------------------------+ |
|  | | [z] rate limited  Worker  <ProviderName> t2 | |
|  | |     retry in 0:58 (rule 10)                 | |
|  | +---------------------------------------------+ |
+--+-------------------------------------------------+
```
- **Wireframe, 1440 px** (detail route: header above the terminal):
```
+----------+-----------------------------------------------------------+
| Sidebar  | Session t1 - <ProviderName> - running   [Resume] [Stop]   |
| (240 px) | paused: none        takeover: off (read only)             |
|          | +-------------------------------------------------------+ |
|          | | SessionTerminal (T-106)                               | |
|          | +-------------------------------------------------------+ |
+----------+-----------------------------------------------------------+
```
- **Signature motion:** Stagger on session rows, once, at most 300 ms, 40 ms step.
- **Inspiration technique borrowed:** 60fps.design: 150 ms hover lift on session cards (transform only).
- **States:**
  - Loading: `LoadingSkeleton` rows while `list_sessions` is pending (`running`).
  - Empty: "No sessions yet. Approved plans start workers here." (`fresh`).
  - Rate limited: `Countdown` to `retry_at`. Resume during backoff returns `rule_blocked` 10, shown as "Blocked by rule 10" (`rate_limited`).
  - Error: `ErrorAlert` (`errors`).

## Behaviour
- Pause reasons in plain words: user, user idle, app in background, taken over, limit errors (resume on Usage), at ceiling, spend cap, kill switch.
- Resume calls `resume_session`. A `rule_blocked` refusal shows "Blocked by rule N: <message>".
- Stop opens an AlertDialog: "Stop this session? The CLI process ends. Files in the worktree stay." Then `kill_session`. Stop is never the primary.
- Login sessions (`kind: "login"`) show "Sign-in in terminal" and use the same detail route.
- The detail route imports the placeholder from `@/features/sessions/terminal` (same feature) and renders `SessionTerminal` with `sessionId` and `kind` from `SessionView`. The list never renders a terminal.
- `takeover` is shown read only. The toggle lives in T-106.
- Session events are full snapshots (`session_changed`): replace the cache, do not merge.
- Do not auto-retry on `rule_blocked` or `rate_limited`.
