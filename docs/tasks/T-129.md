Status: draft

## Goal
Produce everything the review screen shows for one finished task: the unified diff in the worktree, the output of the
verification command (tests, lint) with a status, the parsed HANDOFF.md, and the lead's summary checked against its token
budget. Expose the T-101 review commands. Every text value is marked untrusted; the backend never renders it.

## Design
1. **Diff.** `git -C <worktree> diff <base_commit>` (plus untracked files via `git add -N` in a temp index, never in the
   user's index). Output is capped at 512 KiB; `truncated: true` when capped. The cap is the only limit (T-107: the UI adds none).
2. **Verify run.** The verification command is one configured string (Phase 1 default `make check-fast`; the human
   decides the default, see Notes), run in the worktree through the runner (T-119) with a 15-minute timeout and the
   runner's env allowlist. Status: `passed` on exit 0, `failed` on non-zero, `not_run` if the command was not run. Output
   is capped at 256 KiB, `truncated` flag set. Exit code and command string are recorded.
3. **HANDOFF.** The parser reads the fixed-format `HANDOFF.md` from the worktree (AGENTS.md format: Summary, Files
   changed, Tests run, Hard rules touched, Open risks, Confidence). Output: `Handoff` (ok) or `{ok:false, error}`.
   Free text stays free text. The parser never follows a link or runs a command written in the file.
4. **Summary.** The lead's summary is a text value with `tokens` and `budget`. Token count comes from the lead's `result`
   event (numeric, from the adapter); the backend does not estimate it. `links` are built from task ids and kinds
   (`diff`, `test_log`, `handoff`), never from text in the summary.
5. **Commands.** `list_reviews` (tasks in state running, ready, reviewed, failed), `get_review(task_id)` (assembles
   `ReviewView`), `mark_reviewed(task_id)` (sets `reviewed` on the task record and returns the view). `mark_reviewed` is
   refused for a task that is not `ready`.
6. **Untrusted by construction.** Every string from the worktree, the verify log, the handoff and the summary is
   wrapped in `Untrusted<String>` in Rust, serialized as plain text. No Markdown or HTML conversion anywhere.

## Hard rules touched (docs/HARD_RULES.md) and the test that proves each
| Rule | How this task satisfies it | Test |
|---|---|---|
| 4 | Reads only the task's worktree through `fs_guard`; no CLI home reads | `cargo test -p harness-core review::reads_only_worktree` and `review::no_fs_outside_fs_guard` |
| 4 | Verify and diff never include a denied path's contents | `cargo test -p harness-core review::denied_paths_absent` (planted fake `.claude/` file in the worktree is not read) |
| 1 | Summary tokens are numeric and compared to the budget; over budget is flagged | `cargo test -p harness-core review::summary_over_budget_flagged` |
| 8 | No provider names are rendered by the backend text paths (names come from the strings file on the UI side) | `cargo test -p app review::no_marketing_strings` (greps the module for provider names outside test fixtures) |
| Security | Hostile HANDOFF, diff and log text is returned as data, never executed | `cargo test -p harness-core review::hostile_text_is_data` (fixture with `<img onerror>`, markdown links and `$(rm -rf)`; asserted unchanged and unexecuted) |
| 9 | `mark_reviewed` and verify never approve or start work | `cargo test -p app review::no_approval_side_effects` |
