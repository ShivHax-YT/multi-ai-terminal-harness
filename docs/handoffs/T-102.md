# HANDOFF T-102

## Summary

The Providers screen replaces the T-101 placeholder. Each provider gets a card with plain-text name, install (version and
path as untrusted mono text), binary verification (with the failing checks when verification failed), sign-in and
personal-use status, the backend's own `usable` answer and one plain sentence per blocker. Every card shows its single
next step; the first provider in `list_providers` order that has one gets the screen's only filled button (`min-h-11`),
the others are outline. Data comes only from `list_providers` plus `provider_changed` events; actions are
`refresh_provider_status`, `confirm_personal_use` and `open_provider_login` (then navigate to the login session).

## Open risks / questions

- The brief says "Sign-in runs `confirm_personal_use`, then `open_provider_login`" and also lists Confirm and Sign in as
  separate steps with Sign in disabled until confirmed. I built the second reading: Confirm is its own step (the next step
  while unconfirmed), then Sign in only calls `open_provider_login`. The click handler refuses to call it unless the status
  already says confirmed, and a disabled "Sign in in terminal" is shown next to Confirm so the order is visible.
- `sign_in.state: "unknown"` (binary verified, personal use confirmed) offers "Sign in in terminal" as the next step; the
  CLI's own login shows the true state. If the lead prefers "Check again" for `unknown`, it is one line in `next-step.ts`.
- The brief says `sessionPath(session_id)`; the real helper is `paths.session(session_id)` and that is what is used.
- No fixture or mock scenario carries an `install_hint`, so the mock shows "No install text is available yet."; tests seed one.
  Per the brief's note, an install command is not in the contract (copy-only text in v1).
- Cards use `role="group"` labelled by the provider name, so two "Go to Lead" buttons are told apart by their card, not by
  their own accessible name.
- The mock's `computeUsable` overwrites seeded `usable`, so tests that need an odd `usable` wrap `list_providers` instead.
- Tests read the backend's private `providers` map through a typed cast (test files only) to seed states the scenarios lack.
