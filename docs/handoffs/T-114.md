# HANDOFF T-114

## Summary
Replaced the placeholder `fs_guard` module with the file-access layer. `FileGuard` is the one door (`open_read`,
`read_to_string`, `read_dir`, `metadata`, `create_write`, `exec_resolve`, `register_root`): require an absolute path,
refuse if the lexical form is denied, canonicalize, refuse if the canonical form is denied (deny wins), require a
registered root, do the operation, record one `TraceEvent { path_hash, op, outcome, at }` (SHA-256 of the path, never the
path). The denylist is `compliance/denylist.toml`, embedded with `include_str!`, parsed once, fails closed (empty lists,
bad entries and any `allowed_exceptions` are load errors). `install` makes one guard process-wide; the free functions fail
closed with `NotInstalled` before that.

## Open risks / questions
- Brief path is `src-tauri/crates/harness-core/...` (the lead message said `src-tauri/harness-core`); I used the real crate path.
- Credential strings never appear in Rust (scan allows only `compliance/`), so tests plant canaries by iterating the
  loaded denylist, not by naming `.credentials.json`/`auth.json`. Same coverage, no scan weakening.
- Keychain list holds only the one service name already known in the repo scan; the other providers' names must be
  confirmed by the human on a real install before Phase 3 (never by querying the Keychain from code).
- `no_raw_fs_outside_module` scans `harness-core/src` outside `fs_guard/` for `File::open`, `fs::read*`, `OpenOptions`,
  `std::fs::File` and bare `read_to_string(`, stopping at the first `#[cfg(test)]`. After merge it may flag other Phase 1
  modules (e.g. T-115 hashing a binary, T-105/T-111 file reads). Those modules must route through `fs_guard`, or the lead
  decides on an explicit allowlist; I did not weaken the test. `exec_resolve` deliberately does not open the binary, so
  T-115 needs a content-hash path (for example `codesign` on the resolved path) that does not read a denied directory.
- Hard-linked regular files (nlink > 1) are refused for open and write: conservative, blocks hard-link smuggling, could
  refuse legitimately hard-linked files in a worktree.
- Not handled: Unicode normalization variants (NFC/NFD) in names, and TOCTOU races on directory components (the final
  component is opened with `O_NOFOLLOW`). `exec_resolve` returns any regular executable file, including one in a denied
  home, by design; it checks nothing about the file name.
- Writes allowed only under `Worktree` and `AppData` roots; `Repo` is read-only.
