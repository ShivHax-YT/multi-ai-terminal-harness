# HANDOFF T-007

## Summary
Added `spike/run-both.sh`, the one human-triggered script that closes Phase 0: it runs `spike/preflight.sh` once, then the merged T-002 `claude/run.sh` once, waits `GAP_SECS` (5, readonly, `/bin/sleep`) and runs the T-003 `codex/run.sh` once, strictly in that order (no loop, no background job, no retry, no resume). Codex still runs after a Claude FAIL (human decision 2026-10-26); a signal stops before it. It normalizes each `raw.jsonl` with T-004's jq, checks `hello.txt` byte-exact and lists changed files, prints one table (provider, exit, redacted session id, turns, tokens in/out/cache, estimated cost, warning/rate_limited/unknown counts, changed files, hello, PASS/FAIL), writes `run-both.json`, cleans the scratch dirs unless `--keep`, and exits non-zero if either CLI FAILs. Without the live opt-in it exits 3 and starts nothing; `--dry-run` prints the plan and runs nothing. `spike/PHASE0-REPORT.md` is the template the lead fills from the human's output. Round 2 (below) closes two review blockers (git run on a scratch repo whose config the CLI can write; a normalizer exit status that was thrown away) and ten follow-ups.

## Round 2 (review fixes)
Blocker 1 (compliance-auditor, rule 4 / rule 3 spirit): `git status` ran on the scratch repo, whose config the CLI could write. The old forced-off keys (fsmonitor, hooksPath, untrackedCache) did not stop `filter.<x>.clean` / `filter.<x>.process` drivers (run on stat-dirty files whose `.gitattributes` sets `filter=x`), `include.path`, or `core.worktree`. The old handoff wording "the config keys that start programs forced off" overstated that lock-down and is withdrawn.
- Fix (fail-closed allowlist): before any git command runs on the repo, `scratch_repo_ok` reads the repo config (and `config.worktree` if present) with `git config --file ... --name-only --list` (executes nothing, follows no include) and compares every key with the allowlist the scratch setup writes: `core.repositoryformatversion`, `core.filemode`, `core.bare`, `core.logallrefupdates`, `core.ignorecase`, `core.precomposeunicode` (what `git init` and `git worktree add` wrote in `spike_scratch_repo` / `spike_worktree_add`; no `branch.*` entries are written). Any other key, an unparsable or symlinked file, or a changed layout: no git runs, the row FAILs with the fixed reason "scratch repo config changed", changed files shows "(not listed: repo config changed)". Proof: `config_allowed accepts/refuses <key>` (6 allowed, 19 refused, incl. `foo.bar`), `hostile <name>` (status 3, fixed text, marker absent), `L filter.x.clean / filter.x.process / include.path / core.worktree / unknown key foo.bar` (whole flow: exit 1, marker absent, reasons exactly `["scratch repo config changed"]`, canary never printed), and the controls `a plain git status DOES run the filter` (the fixtures are not vacuous). Positive: `changed_files on an untouched scratch config`, `A: run-both.json lists hello.txt`.
- Also set: `GIT_CONFIG_GLOBAL=/dev/null` with `GIT_CONFIG_NOSYSTEM=1` (static test; behaviourally redundant with `HOME=/nonexistent`); the existing forced-off keys kept.
- Git version: `GIT_CONFIG_COUNT` needs git 2.31 and `GIT_CONFIG_GLOBAL` 2.32. `git_new_enough` runs `git --version` (found by `spike_tool_path git`, the probe path's native-tool check) and below 2.32 nothing else runs: "(not listed: git too old)", not a FAIL by itself. Proof: `git version [2.30.1 ...]: not listed, git too old`, `only --version was run`. (I did not use `spike_run_timed`: it needs the runner's gate; a direct `--version` call on the probe-checked tool is simpler and equally closed.)
- Extra holes closed in the same spirit (found while designing the tests): (a) the worktree's own `.git` file is CLI-writable and can redirect git to another git dir; the git dirs are now pinned from the path with `GIT_DIR`/`GIT_COMMON_DIR` (`a rewritten .git file is not followed`, with a control); (b) a nested repository (what a submodule is) has its own config, so `status --ignore-submodules=all` (`a nested repository's filter driver is not started`, with a control); (c) the library's `spike_cleanup` (frozen) also runs `git worktree list/remove/prune` on that repo, so `cleanup_one` runs it only if the allowlist still passes, else the dir is left and reported (`L: the claude scratch dir is left ...`).

## Open risks / questions
- **The live path of `run-both.sh` has not run against real CLIs** (by design). It is tested in a sandbox copy of `spike/` whose run scripts and preflight are fakes. The sandbox copy of `lib/common.sh` has one appended line turning the live gate into a no-op, because a test must not set the live opt-in; nothing in the sandbox can start a provider CLI, and a test asserts (by content and by sha256, also against HEAD) that the real `lib/common.sh` is unchanged. The real gate is tested separately (exit 3 with fakes on PATH).
- **Signals**: INT/TERM/HUP are recorded and acted on when the current child returns (bash runs traps after a foreground child). `runner.pl` moves the CLI into its own process group, so a terminal Ctrl-C does NOT reach the CLI: `run.sh` and the CLI keep running until the CLI ends or the 120 s watchdog kills it, and only then does `run-both.sh` stop; Codex still never starts after a signal. A TERM sent to `run-both.sh` alone does not interrupt a running child either.
- **TOCTOU on the config check**: the check and the `git status` are separated by milliseconds; the CLI has exited by then, but an orphaned child process of the CLI could still write. Not provable here.
- **Diff stat**: the brief asks for `git status --porcelain` names, so the table shows changed file names (not a `git diff --stat`).
- `GIT_CONFIG_GLOBAL=/dev/null` has only a static test: `HOME=/nonexistent` under `env -i` already keeps the user's config out, so no behavioural test can tell them apart.
- The PASS rule requires `tokens_known` true on the result. `codex-sample` contains 2 `unknown` events (synthetic, T-003 fixture), so its row prints the "needs mapping (T-004)" note while still PASS.
- If the human's Claude run leaves a second directory under `$ROOT/claude/` the row is FAIL ("not exactly one capture").
- Round 2 was done in worktree agent-aa3f588c5a6b98ca1 (branch worktree-agent-aa3f588c5a6b98ca1, base 0b4097a), not in agent-ad4c1090a68e70c0d, as the coordinator directed; the commit is to be rebased onto the T-004 base by the lead.
