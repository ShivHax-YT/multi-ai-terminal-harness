## Summary
Added `spike/run-both.sh`, the one human-triggered script that closes Phase 0: it runs `spike/preflight.sh` once, then the merged T-002 `claude/run.sh` once, waits `GAP_SECS` (5, readonly, `/bin/sleep`) and runs the T-003 `codex/run.sh` once, strictly in that order (no loop, no background job, no retry, no resume). Codex still runs after a Claude FAIL (human decision 2026-10-26); a signal received before the pre-Codex check stops before it. Without the live opt-in it exits 3 and starts nothing; `--dry-run` prints the plan and runs nothing. `spike/PHASE0-REPORT.md` is the template the lead fills from the human's output. Round 2 (below) closes two review blockers (git run on a scratch repo whose config the CLI can write; a normalizer exit status that was thrown away) and ten follow-ups.

## Open risks / questions
- **TOCTOU between the checks and git (new, not closable in shell).** `wt_path_ok`, `scratch_repo_ok` and the config allowlist are checked, then git runs milliseconds later. Only a detached child process the CLI left behind could still change the files in that window (the CLI itself has exited); a shell cannot make the check and the git call atomic.
- **`init.templateDir` (new).** A user's global `init.templateDir` can copy files, and an included template can add config keys, into a new scratch repo. Any key outside the allowlist makes the fail-closed check refuse: a false FAIL ("scratch repo config changed") on a live run with such a setup. The two `init.*` object/ref format settings are handled (fix 5); `templateDir` is not, on purpose (the template content is not ours to vouch for). Workaround for the human: unset it for the run.
- **The live path of `run-both.sh` has not run against real CLIs** (by design). It is tested in a sandbox copy of `spike/` whose run scripts and preflight are fakes. The sandbox copy of `lib/common.sh` has one appended line turning the live gate into a no-op, because a test must not set the live opt-in; nothing in the sandbox can start a provider CLI, and a test asserts (by content and by sha256, also against HEAD) that the real `lib/common.sh` is unchanged. The real gate is tested separately (exit 3 with fakes on PATH).
- **Signals**: INT/TERM/HUP are recorded and acted on when the current child returns (bash runs traps after a foreground child). `runner.pl` moves the CLI into its own process group, so a terminal Ctrl-C does NOT reach the CLI: `run.sh` and the CLI keep running until the CLI ends or the 120 s watchdog kills it, and only then does `run-both.sh` stop; Codex still never starts after a signal, except in the instants between the last check and the launch (see Round 4b D). A TERM sent to `run-both.sh` alone does not interrupt a running child either.
- **TOCTOU on the config check**: the check and the `git status` are separated by milliseconds; the CLI has exited by then, but an orphaned child process of the CLI could still write. Not provable here.
- **Diff stat**: the brief asks for `git status --porcelain` names, so the table shows changed file names (not a `git diff --stat`).
- `GIT_CONFIG_GLOBAL=/dev/null` has only a static test: `HOME=/nonexistent` under `env -i` already keeps the user's config out, so no behavioural test can tell them apart.
- The PASS rule requires `tokens_known` true on the result. `codex-sample` contains 2 `unknown` events (synthetic, T-003 fixture), so its row prints the "needs mapping (T-004)" note while still PASS.
- If the human's Claude run leaves a second directory under `$ROOT/claude/` the row is FAIL ("not exactly one capture").
- Round 2 was done in worktree agent-aa3f588c5a6b98ca1 (branch worktree-agent-aa3f588c5a6b98ca1, base 0b4097a), not in agent-ad4c1090a68e70c0d, as the coordinator directed; the commit is to be rebased onto the T-004 base by the lead.
