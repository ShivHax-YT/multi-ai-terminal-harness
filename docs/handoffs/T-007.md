# HANDOFF T-007

## Summary
Added `spike/run-both.sh`, the one human-triggered script that closes Phase 0: it runs `spike/preflight.sh` once, then the merged T-002 `claude/run.sh` once, waits `GAP_SECS` (5, readonly) and runs the T-003 `codex/run.sh` once, strictly in that order (no loop, no background job, no retry, no resume). Codex still runs after a Claude FAIL (human decision 2026-10-26); a signal stops before it. It normalizes each `raw.jsonl` with T-004's jq, checks `hello.txt` byte-exact and lists changed files, prints one table (provider, exit, redacted session id, turns, tokens in/out/cache, estimated cost, warning/rate_limited/unknown counts, changed files, hello, PASS/FAIL), writes `run-both.json`, cleans the scratch dirs unless `--keep`, and exits non-zero if either CLI FAILs. Without the live opt-in it exits 3 and starts nothing; `--dry-run` prints the plan and runs nothing. `spike/PHASE0-REPORT.md` is the template the lead fills from the human's output.

## Open risks / questions
- **The live path of `run-both.sh` has not run against real CLIs** (by design). It is tested in a sandbox copy of `spike/` whose run scripts and preflight are fakes. The sandbox copy of `lib/common.sh` has one appended line turning the live gate into a no-op, because a test must not set the live opt-in; nothing in the sandbox can start a provider CLI, and a test asserts the real `lib/common.sh` has no such line. The real gate is tested separately (exit 3 with fakes on PATH).
- **Signals**: INT/TERM/HUP are recorded and acted on when the current child (run.sh, at most ~120 s watchdog, or the 5 s sleep) returns, because bash runs traps after a foreground child. Ctrl-C from a terminal also reaches the running child directly. A TERM sent to run-both.sh alone does not interrupt a running child.
- **Diff stat**: the brief asks for `git status --porcelain` names, so the table shows changed file names (not a `git diff --stat`). Cheap to add if the lead wants line counts.
- **Git config isolation** uses `GIT_CONFIG_COUNT/KEY/VALUE` (git 2.31 or newer, March 2021; macOS system git is newer). On an older git the three overrides would be ignored silently; `HOME=/nonexistent` and `GIT_CONFIG_NOSYSTEM` still apply.
- The PASS rule requires `tokens_known` true on the result, not only numeric `input`/`output` (the normalizer writes 0 for missing counts, so numeric alone would pass an empty usage). `claude-limits`, `codex-failure` come out FAIL; the four sample/routine/item-warning outputs come out PASS. Note `codex-sample` already contains 2 `unknown` events (the two synthetic unknowns of the T-003 fixture), so its row prints the "needs mapping (T-004)" note while still PASS.
- Disk in this sandbox was nearly full during `make check-fast` (other worktrees hold 2-4 GB of `target/` each); I deleted only my own `src-tauri/target`.
- If the human's Claude run leaves a second directory under `$ROOT/claude/` the row is FAIL ("not exactly one capture"); a single `run-both.sh` run creates exactly one per CLI.
