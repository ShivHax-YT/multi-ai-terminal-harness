## Open risks / questions

1. **Exact execution blocker:** the current unprivileged path-checking architecture cannot atomically enforce its
   custom protected-path policy across real-directory renames, future handle use, Git, workers and test descendants.
   A private directory, `O_NOFOLLOW_ANY`, descriptor pinning or post-operation checks do not supply that boundary.
   It needs a separately reviewed kernel-enforced broker/isolated execution environment, including allowed CLI auth.
   The existing deployment decision explicitly excludes blanket App Sandbox inheritance. No such broker was
   silently substituted or installed. Native repository import/worktree/worker operations remain unavailable.
2. General read handles/checks and guard traces remain limited; the trace is not a syscall-open audit. No native
   repository-reading workflow is enabled on them. All file mutation remains refused.
3. Launch identity is a main-image gate, not a filesystem, library, plugin, tool or descendant sandbox. In particular,
   the current Claude binary disables library validation. Fixed version/auth commands, neutral cwd and allowlisted
   environment do not justify exposing arbitrary model/worker commands.
4. Probe capture has a 64 KiB output ceiling and a 20-second deadline **after** synchronous OS launch returns; it does
   not bound AMFI/OS launch latency. Cancellation uses Foundation's owned-process API. If SIGTERM has not stopped the
   CLI within the cleanup grace period, a retained reaper holds the slot and the result is cleanup pending. No hard
   kill or arbitrary-descendant cleanup guarantee is claimed.
5. The human login mode is deliberately interactive; it has no scheduler/model prompt and no captured login output.
   It requires a foreground Terminal, transfers its foreground group to the CLI, and restores it afterward. Same-UID
   debugging, signalling and modification of the trusted harness executable are outside the filesystem-swap threat
   model. No claim of protection against a fully compromised same-user process is made.
6. Plans/sample results remain in memory. There is no real isolated worker run, actual Git diff/test evidence,
   durable dispatch/approval/usage recovery or independent AI worker review. Native Usage/Settings/Sessions screens
   say unavailable; their unused read stubs still contain fixtures. The browser demo is explicitly labelled.
7. Reviewer and compliance-auditor roles reviewed the security-sensitive changes. The required separate-vendor
   model-code review was not run through a headless inference path: that path has not met full-integrity/execution
   acceptance. No review pass or completed MVP is inferred from the local role reviews.
8. This is a local debug app; signing/notarization/distribution acceptance and cross-Mac installation were not done.
