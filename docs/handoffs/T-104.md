## Open risks / questions
Deviations from the brief text and lead notes:
1. `SampleFlow` renders for any `sim-N` plan id in both runtimes, not only the browser demo, because the sample Lead form creates `sim-N` plans natively too and links to them. Its native branch is unchanged (approval disabled, no `sim_run`, no PTY import).
2. `/plans` with no id now shows the newest `list_plans` entry (or the empty state); it no longer auto-shows the latest sample plan. Sample plans are reached from the Lead form link.
3. Edit controls appear for `draft` only, as the brief says, so the "voids approval" warning is informational in the UI (an approved plan is read-only). The mock still accepts edits on an approved plan; the "Edited after approval. Approve again." text is tested through the mock directly.
4. Fallback "outside the plan" means a provider no task in the plan runs, matching the mock's rule 9 check. Fallback options are `MVP_PROVIDER_IDS` plus providers already on that task.
5. The brief's `(api_key, ready)` scenarios for the rule 7 test do not hold plans, so the rule 7 test uses `plan_draft` with a Gemini task set through the mock client.
6. Extras not in the brief: acceptance editing and remove-task (both are existing `PlanEdit` kinds), and an "Other plans" list when more than one plan exists.

8. Task cards are one stacked layout at all widths; the 1440 px table wireframe is not built (no visual check possible here). Human check of `pnpm dev` is still pending.
