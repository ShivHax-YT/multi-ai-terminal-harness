# HANDOFF T-134

## Summary

Human terminals for Claude Code and Codex still open through the closed `--provider-session` path. Stop signals that pty's foreground group with `TIOCSIG` and does not call `kill` on a saved pid. The provider slot stays occupied until the process is waited, including a failed stop. A newer vendor-signed release can still open a human terminal. Automated tasks for that release get `release_unreviewed`, and `usable.lead` / `usable.worker` stay false. Automated workers stay off. Grok, Kimi, Gemini, and GLM stay without a human Open button.

The original seven-finding report is still missing. An earlier draft of this handoff quoted a transcript and treated that list as recovered. That claim is withdrawn. The historical seven are not claimed resolved.

The confirmed list is the eight-item review. Findings 2–8 were fixed at `812755a`. Finding 1 was still open there: `input` and ordinary `keypress` cleared the user turn after `beforeinput` re-armed it, and before xterm's already-queued composition timer. This follow-up keeps that turn open until the nested clear, which is queued so it runs after that timer.

A unit test cannot prove a keystroke came from a person. The new composition tests dispatch `beforeinput`, `input`, and `keypress` before a timer that was queued during `compositionend`. They are not a WebKit IME session.

Original reviewer finding 5, quoted from `agent-ac3de0c0a06d4bd7e.jsonl`:

> 5. **`src-tauri/crates/harness-core/native/launch_gate.swift:32` (medium): Ctrl-Z can freeze the terminal.** If the CLI suspends itself, `waitUntilExit` keeps blocking and nothing regains the foreground or sends SIGCONT. The session shows Running, and only Stop recovers it.

That freeze is fixed. The human terminal has no job-control shell. While the owned CLI is stopped, `waitpid` with `WUNTRACED | WNOHANG` reports the stop, and `SIGCONT` goes to the pid that wait just returned. A stopped child has not been reaped, so that pid has not been reused. An exit status is not signaled, and the pid is not saved for a later kill. `TIOCSIG` Stop, the slot-until-exit ceiling, and the human-only input path are unchanged.

## Open risks / questions

- Ctrl-Z no longer leaves the CLI stopped. The wrapper continues that owned child. A real Ctrl-Z keystroke in the WebKit bundle was not typed; the regression is `/bin/sh` sending itself `SIGTSTP`.
- A process that ignores SIGHUP stays in `stopping` and holds the slot. Quit waits up to 2 seconds on the same `TIOCSIG` path and does not send SIGKILL to a pid. The process can still be alive when that wait ends. That cap was left as documented.
- The mode prefix on a wrapped ring restores bracketed paste, mouse, and alternate-screen private modes. It is not a full screen reconstruction. If the ring wraps in the middle of the alternate screen, the tail can still be the wrong buffer.
- No real IME was typed into the WebKit bundle. The new test follows the browser event order in jsdom. It is not a human input method.
- Grok: Open unavailable. `compliance/vendor-pins.toml` has no Grok team id, signing identifier, or reviewed hash. None was invented, and there is no in-repo `grok login` argv. `grok -p` and `grok agent stdio` are not launched.
- Kimi: Open unavailable for the same reason. `kimi acp` is not launched.
- Gemini: Open unavailable. API key only, and this repo does not name the key's environment variable or flag. `session_env` does not pass a key. Settings storage is not implemented. No `--provider-login=gemini` and no Google sign-in.
- GLM: Open unavailable. It is not a `glm` binary, and `glm` was not added to CLI names or `vendor-pins.toml`. Reusing the Claude pin would still need a base URL this repo never names. `CLAUDE_CONFIG_DIR` was not set.
- Automated workers, adapter start/send, worktrees, and `usable.lead` / `usable.worker` stay off for every provider, including Claude and Codex.
