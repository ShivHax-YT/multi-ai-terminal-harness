# HANDOFF T-004

## Summary
Wrote the stack-neutral adapter contract (`docs/spec/adapter-interface.md`: eight methods including the approved
`loginArgv()`, the six-state machine as a transition table, per-CLI mapping tables with a Source column and marked ignored
lists) and one JSON Schema 2020-12 for the normalized event (`docs/spec/event.schema.json`, 11 event types, closed transport
enum `headless | acp`). Proved it with two jq normalizers (`spike/normalize/claude.jq`, `codex.jq`) run over every committed
fixture, nine golden outputs, and `spike/tests/test_normalize.sh` (421 checks with no observed capture present). The
human's four decisions are implemented as written: `loginArgv()` returns only the CLI's own login command; each Codex `exec`
is 1 turn; an unknown or missing Claude `rate_limit_event` status is `rate_limited` (`claude_unknown_limit_status`) and only
`allowed`/`allowed_warning` are `limit_notice`; `cost_is_estimate` is always true. Codex `item.error` items are warnings.

## Open risks / questions
- **Codex top-level `error`**: the brief maps it to a fatal `error{stream_error}`. If Codex 0.162 also sends non-fatal `error` events (for example retry notices) in a successful run, the live capture will show an `error` event. The observed-capture rules in the brief do not fail on it (they check `unknown`, `result`, `rate_limited`, tokens), so a lead review of the first capture should look for it.
- **T-124 versus T-004 on `rate_limited`**: T-124's draft enters `rate_limited` "on a `rate_limited` event"; the T-004 brief (state machine row 7) enters it at invocation exit and counts once per invocation. The spec follows T-004. T-124 needs a one-line fix before it is approved.
- **`loginArgv` words** (`claude auth login`, `codex login`) are written in the capabilities table as "T-121/T-122 confirm". They are not observed.
- **Observed captures**: `observed.jsonl` must hold one invocation (exactly one `result`). Save a resume capture as a separate `observed-resume.jsonl`. No golden file is required for observed files (the test prints a NOTE); the lead may add `spike/normalize/expected/<cli>-observed.jsonl` after reviewing the capture.
- Only jq 1.7 was available here. The jq code avoids 1.7-only syntax (`if` without `else`, `abs`, `toarray`, `ltrimstr` on non-strings); jq 1.6 was not run, and number formatting such as `1.0` could differ between jq versions (no fixture uses such a literal). A `$type` parameter shadowed the `type` builtin during development (fixed by naming it `$etype`), which is worth remembering for T-121/T-122 when porting the mapping.
- Claude `thinking_tokens` and the hostile fixtures are synthetic shapes (the live field names of `thinking_tokens` were not provided).
