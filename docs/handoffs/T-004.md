# HANDOFF T-004

## Summary
Wrote the stack-neutral adapter contract (`docs/spec/adapter-interface.md`: eight methods including the approved
`loginArgv()`, the six-state machine as a transition table, per-CLI mapping tables with a Source column and marked ignored
lists) and one JSON Schema 2020-12 for the normalized event (`docs/spec/event.schema.json`, 11 event types, closed transport
enum `headless | acp`). Proved it with two jq normalizers (`spike/normalize/claude.jq`, `codex.jq`) run over every committed
fixture, nine golden outputs, and `spike/tests/test_normalize.sh` (421 checks with no observed capture present). The
human's four decisions are implemented as written: `loginArgv()` returns only the CLI's own login command; each Codex `exec`
is 1 turn; an unknown or missing Claude `rate_limit_event` status is `rate_limited` (`claude_unknown_limit_status`) and only
`allowed`/`allowed_warning` are `limit_notice`; `cost_is_estimate` is always true. Codex `item.error` items are warnings.

## Open risks / questions
- **Codex top-level `error`**: the brief maps it to a fatal `error{stream_error}`. If Codex 0.162 also sends non-fatal `error` events (for example retry notices) in a successful run, the live capture will show an `error` event. The observed-capture rules in the brief do not fail on it (they check `unknown`, `result`, `rate_limited`, tokens), so a lead review of the first capture should look for it.
- **T-124 versus T-004 on `rate_limited`**: T-124's draft enters `rate_limited` "on a `rate_limited` event"; the T-004 brief (state machine row 7) enters it at invocation exit and counts once per invocation. The spec follows T-004. T-124 needs a one-line fix before it is approved.
- **`loginArgv` words** (`claude auth login`, `codex login`) are written in the capabilities table as "T-121/T-122 confirm". They are not observed.
- **Observed captures**: `observed.jsonl` must hold one invocation (exactly one `result`). Save a resume capture as a separate `observed-resume.jsonl`. No golden file is required for observed files (the test prints a NOTE); the lead may add `spike/normalize/expected/<cli>-observed.jsonl` after reviewing the capture.
- Only jq 1.7 was available here. The jq code avoids 1.7-only syntax (`if` without `else`, `abs`, `toarray`, `ltrimstr` on non-strings); jq 1.6 was not run, and number formatting such as `1.0` could differ between jq versions (no fixture uses such a literal). A `$type` parameter shadowed the `type` builtin during development (fixed by naming it `$etype`), which is worth remembering for T-121/T-122 when porting the mapping.
- Claude `thinking_tokens` and the hostile fixtures are synthetic shapes (the live field names of `thinking_tokens` were not provided).

## Round 2 (review fixes, branch T-004-r2)

### What changed
1. **Coverage check was vacuous (blocker).** `key_listed` now uses `. as $e | $e == $k or (($e|endswith("/*")) and ($k|startswith($e[0:-1])))`. The old form evaluated `.[0:-1]` against `$k`, so for Claude (which has `result/*`) every key counted as listed. The check is now the function `rawkey_problems` (shared by the per-fixture loop and the new tests). Fixing it exposed one real test gap: the independent key derivation emitted a bare `user` (and a bare `assistant` for every assistant line), which no list contains; assistant and user lines are now keyed only by their content blocks (plus `assistant` when an `error` string is present). Proof: unit tests for `key_listed` (listed and not listed, Claude and Codex, including `brand_new_type`, `system/whatever`, `user`, `resultx/success`), and 9 mutation tests that rename one key inside `mapped_keys` of a scratch copy (`assistant:tool_use`, `system/init`, `rate_limit_event`, `result/*`, `assistant:text`, `user:tool_result`, `turn.completed`, `thread.started`, `item.completed:agent_message`), each asserting the real normalizer passes and the check FAILS against the broken copy; one more drops `assistant:thinking` from `ignored_keys`.
2. **Turn rule (blocker, rule 1).** The spec's Turns paragraph says an invocation that ends with no `result` (Codex bare top-level `error`, crash, watchdog kill, killed Claude run) still counts at least 1 turn; the scheduler counts 1 turn at dispatch and reconciles with `result.turns` when larger. Tests grep the spec for the three phrases.
3. **`clip`** (both normalizers) cuts to the length first, then cleans. Output is unchanged (cleaning replaces 1:1). The old code took 20 s for a 32k-ESC line pair; the test with 32k ESC in every text field of both normalizers now finishes well under 2 s (asserted with `jq now`).
4. **State machine.** Rows 3 to 6 now say "no `rate_limited` seen"; row 7 covers `spawning` and `running` and sets a `limit_seen` flag; new row 11 (success `result` then non-zero exit -> `exited`, invocation `is_error` derived from the exit, the `result` event is not rewritten); explicit "Invocation flags" paragraph (transition function takes `(state, event, invocation_flags)`) and a "Precedence when the child ends" paragraph (`limit_seen` wins over rows 3 to 6 and 11; otherwise order 3, 11, 4, 5, 6). Tests grep each statement.
5. **Schema integers.** `reset_at`, `retry_after_s`, `duration_ms` are `integer` (turns and tokens already were); `utilization` stays `number` (a fraction such as 0.9). The Claude normalizer floors `resetsAt` and `duration_ms` so a fractional raw value cannot break the integer type. Tests: schema type checks, a fractional-input test, and a validator check that a fractional `reset_at` fails.
6. **Codex tool items.** An item with no id (or an empty id): the `item.started` event is dropped, and `item.completed` emits both `tool_call` and `tool_result` with the same `line<N>` id (N = the completed line), so the pair always matches. `status: "declined"` -> `tool_result.is_error` true. `exit_code` as a string is parsed (`"0"`, `"0.0"` ok; `"2"` error); a non-numeric string, empty string, array or object is an error (fail safe); null/missing is not.
7. **Claude `api_error_status`** given as the string `"429"` maps like the number 429 (`claude_result_429`); `"500"`, `"abc"` and a success result do not. The existing weird-input test now expects 2 rate_limited (the old fixture line `"api_error_status":"429"` is now a limit by design).
8. **Observed-capture check** now looks for email-shaped text (`[^ @]+@[^ @]+\.[a-zA-Z]{2,}`) instead of any `@`; tests prove `@types/node` passes and `someone@example.com` is caught.

### Golden changes
None. All nine golden files are byte-identical: no committed fixture has a tool item without an id, a declined item, a string exit code, a string 429, or a fractional number, and `clip` output is identical.
