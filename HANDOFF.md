# HANDOFF T-006

## Summary
Round 7 of T-006 (worker HANDOFF format and parser), structural: the interface is now `parse.sh --root <worktree>` and the parser reads exactly <root>/HANDOFF.md (a second positional argument is a usage error, exit 2). The bash wrapper only checks arguments and then execs ONE perl process under env -i; that process walks the root from /, opens the file once, reads it into memory, checks everything and prints the JSON once at the end. No temp file, no copy, no here-string, no jq, no awk, nothing reopened by path.
Provider CLI homes are now refused by identity: the homes come from getpwuid and from HOME (as data), each candidate is stat-ed, and the (device, inode) of every walked directory is compared, so HOME tricks, case changes and bind mounts do not help.
The spec now has an honest threat model: guarantees hold for filesystem state that is not changing during the parse; the caller must have the worker's process group exited and reaped first; a concurrent same-user process is out of scope (Phase 4 worker sandboxing is the control). Every "closes the race" style claim is removed.

## Open risks / questions
- Out of scope, by decision of the lead: a concurrent process running as the same user can race or ptrace the parser. The spec says so. Precondition for the scheduler: the worker's process group has exited, been killed if needed, and been reaped before parse.sh runs. Phase 4 worker sandboxing is the control. The race tests only show that a lost race never printed the outside canary in 200 runs; they are not a proof.
- In the race runs here the parser almost always saw the swapped state and refused (0 or 1 successful parses in 100), so those runs exercise the refusals more than the mid-walk window.
- The post-read fstat compares device, inode, link count and size with the first fstat; it is a consistency check, not a defence against a concurrent writer.
- Case-insensitive filesystems (APFS default): the root is compared with what getcwd reports, so a root typed with different letter case is refused (fails closed). Callers must pass the exact physical path. Not tested on macOS.
- Decisions I made (lead to confirm): root problems (not a directory, missing, relative, too long, dot components) are exit 2 and a symlink or a directory that cannot be entered is exit 1; HOME unset or relative is no longer an error while getpwuid gives a home, and only "no home known at all" is exit 3; PATH_MAX is checked on the root string (length at or above PATH_MAX is refused, exit 2) before any filesystem access; the JSON is now one compact line (jq printed it pretty); warnings inside perl are muted and any unexpected perl failure is exit 3 with a fixed message; a failing tty probe by bash itself is the only O_RDWR open strace sees and is excluded in the test.
- The wrapper checks that /usr/bin/perl is executable (else exit 2) and uses /usr/bin/env -i with PATH=/usr/bin:/bin. If a platform has perl elsewhere the parser needs a one-line change; this is intentional (no PATH search).
- Brief deviation (recorded in the spec): the brief says jq --arg; jq and awk are not used any more. The intent, no shell interpolation of content, is kept: content never leaves perl strings and reaches JSON through JSON::PP with ASCII escaping.
- The lead must still check that files_changed paths are inside the worker's owned files and that task_id is the dispatched task.
- No shared-file change is needed for this task.

### Round 7 (structural)
Decision, implementation, tests.
- 1 One file: decision, interface `--root <worktree>` reads only HANDOFF.md. Implementation: the wrapper accepts exactly two arguments; the leaf name is one constant in the perl program. Tests: "a second positional argument" (rc 2), "a positional argument before --root", "the old interface (a file path only)", "--root given twice", "a subdirectory HANDOFF.md is never read" (sub/ and a/b/ canaries), "other names are not read", "the parent directory's HANDOFF.md is not read", "a HANDOFF.md in the caller's working directory is not read".
- 2 One process, no temp files: decision, perl does walk, open, read, checks and JSON. Implementation: exec /usr/bin/env -i PATH=/usr/bin:/bin LC_ALL=C /usr/bin/perl -e PROG -- root HOME; @INC reduced to absolute entries before any use. Tests: listings of the root and TMPDIR before and after (success and refusal), "an unusable TMPDIR does not matter", "a read-only root parses", strace block, source guards, env block, "fake perl and env on PATH are not used".
- 3 CLI homes by identity: implementation as in the Summary. Tests: see Hard rules touched. The passwd-independent seam is a sandbox copy of parse.sh (sed) that takes the account home from HANDOFF_TEST_PWDIR and does not scrub the environment; "the sandbox copy changes exactly the two seam lines" checks the copy against the real file.
- 4 Honest threat model: docs/spec/handoff.md has "Threat model" with guarantees (for a filesystem that is not changing), the caller precondition and the out-of-scope list. Tests: spec text checks (no "closes the race", names Phase 4, reaped, out of scope).
- 5 Tests: rewritten call sites (fixtures are copied into a per-test sandbox root as HANDOFF.md), every content assertion kept. New: PATH_MAX (string at and above the limit, a real deep tree just under it parses, one more component is refused with PATH_MAX in the message), mount tests (tmpfs root parses; a HANDOFF.md bind-mounted from /dev/shm is refused as crossing a mount; seam with a bumped st_dev).
- Removed or changed assertions: 169 of the 407 distinct old assertion descriptions no longer appear verbatim; about 60 were removed outright and about 110 were re-expressed for the root-only interface (old total 843 passes, new 901). Removed with the feature: arbitrary and relative input paths, outside-root and dot or dotdot input components, option-looking and hostile file names, awk-assignment names, the dash-name matrix (about 35); temp dir, trap and signal behaviour (INT, HUP, TERM, QUIT runs, temp dir removed, signals ignored around mktemp, unusable TMPDIR is exit 3, one final cat; about 12); external tool failures and absences (failing jq, awk, tr, wc, perl copy and character check, jq missing, iconv guard, scrub prefix on every perl call; about 12); / and /proc as a root with an input on another device (replaced by the mount tests, 8). Changed: symlink, hard link, FIFO, directory and device tests now use HANDOFF.md in the root with the same assertions; root symlink and root swap tests lost the input variants; the CLI home tests moved from path strings to identity, and the one for the Claude JSON file with HOME as the root was dropped because a file cannot be a root (the JSON file is still in the identity set); "HOME unset" and "HOME relative" were internal error rc 3 and are now rc 0 while the account database gives a home (rc 3 only with no home at all, tested through the seam); the lax Encode stub and lstat override tests run the sandbox copy, which now keeps PERL5OPT by dropping env -i instead of the old prefix; the old PERL5OPT test of the real parser is kept with more variables. New assertion counts are in the Tests run section.
- The parser output changed shape slightly: the same keys in the same order, but one compact line instead of jq's pretty print (test "stdout is exactly one JSON line").
